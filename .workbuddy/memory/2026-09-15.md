## war3map.w3e (v11) 格式：实测标定结论

目标：给 mapgen 工具链加「高度 / 悬崖 / 树木 / 野怪」，先搞清楚 w3e 二进制布局。

### 确定性结论（多张官方地图交叉验证）
- v11 = **7 字节/角点**（文件大小 260816 - header 73 = 37249×7 整除；v12 是 8 字节，
  所以只支持 v12 的 Wartergen 不能直接用在 1.27a 地图上）。
- 布局：`u16 groundHeight | u16 waterHeight(+0x4000 boundary1) | u8 flags<<4|texture | u8 groundVar<<3|cliffVar | u8 cliffTexture<<4|layerHeight`
- **高度公式**（HiveWE wiki）：WE 显示高度 = `(groundHeight - 8192 + (layer - 2) * 512) / 4`
  - 8192 = ground zero；**layer 零层 = 2**（不是 0）；**每层 = 512 原始单位 = 128 WE 单位**
  - LostTemple layer 分布 {2:8721, 4:7434, 3:4607, 1:2660, 0:1859, 5:640} 印证零层为 2
- **水面标志位是 0x40，不是 0x80**
  - 判据：(真实地面高度 < 水面高度) 与各位的吻合度 → IceCrown 96.8%，LostTemple 99.8%
  - `patch_w3e.py:155,159` 用 `flag_byte |= 0x80` 表示水，是**错的**（0x80 = boundary flag 2）
- flags 完整定义：`0x10 ramp` `0x20 blight` `0x40 water` `0x80 boundary2`
- layerHeight 上限 14，**layer = 15 会导致加载崩溃**；地形 gelatin: gh 可用范围约 [-8192,+8192] 原始单位（≈ ±16 层精细起伏）
- 悬崖崖面由相邻角点 layer 差自动涌现，不需要额外数据

## 斜坡（ramp）机制 —— 关键实测结论
判据：用官方地图的 war3map.wpm（路径图，4 倍分辨率，640x640，行自顶向下；
正常可走陆地众数值 = 64，其余为障碍）统计「层差 → 可走性」：
- 层差=0：53% 可走（其余是不可玩的外圈）
- 层差=1：13.6% 可走
- 层差=2：0% 可走
再按 ramp 标志位 (0x10) 拆分层差=1 的干净陆地瓦片：
- **无 ramp 标志：692 个，可走 0 个（100% 被挡）**
- 有 ramp 标志：190 个，可走 120 个（63.2%）
→ 层差一律产生不可走的崖面，**必须显式写 flags |= 0x10 才有斜坡**。

### 真实斜坡的角点几何（LostTemple 实测）
角点网格里，层值在某一列由 L→L+1 跳变；斜坡标志被打在**跨越该跳变线的 3 条角点列**上
（低侧 2 条 + 高侧 1 条），沿跳变方向连续延伸 → 得到 **2 格宽的通道**。
例：层 1 1 [1|2] 2 2 → ramp 打在 R R R 三列。

## 下午：地形连通性打通 + 发现并修掉「边界外」标记这个严重 bug

### 修正上文一处结论
上面「层差=0：53% 可走（其余是不可玩的外圈）」里的「外圈」现在查清了：
**是 w3e 的 0x80（flags）和 0x4000（waterHeight）两个「地图边界外」标记**，
LostTemple 用它圈掉了 40% 的角点，带这两位的瓦片寻路可走率 **0%**。
另外 wpm magic 实测是 **"MP3W"**（不是 MPWN），v1。

### 改掉的三类问题
1. **无法刻坡（连通性永远失败）** —— 旧 `carve_ramps` 要求候选崖边「两侧紧邻瓦片都是平地」，
   而 `limit_neighbor_jump` 会把落差摊成多格宽的过渡带，两侧都不是平地 → 候选边全部落空。
   换成：每块台地作节点 → 多源 Dijkstra（平地代价 1 / 崖壁 6 / 贴地图边 +8）扩张得到台地邻接图
   → Kruskal 最小生成树 → 沿最省路径逐瓦片铺 0x10。**算法上保证连通**。
2. **地形碎片化** —— 两个根因：
   (a) `--octaves` 默认 3 太高，改 2；
   (b) 更关键：土地高度用**秩均匀分位**，等于强制每层各占 25% 土地 → 马赛克。
   新增 `--level-bias`（对 land_q 取幂，默认 2.0）还原重尾分布。
   效果：台地 34 → 10 块，斜坡 33 → 6 条。
   另加 `--smooth`（3x3 众数滤波，默认 2，两次即收敛）抹单角点毛刺。
3. **boundary 位** —— 旧代码保留模板的 0x4000 却清掉 0x80，导致整图 40% 被 WE 判成地图外。
   改为 `--boundary ring`（默认，整图清零 + 只最外一圈保留）/ `none` / `keep`；blight 位照旧保留。

### 连通性自检口径修正
旧口径拿「陆地连通块数」和「可走连通块数」直接比 —— 前者含崖壁瓦片，口径不同**永远不可能相等**。
正确判据：**逐个陆地岛检查岛内可走瓦片是否同属一个可走连通块**。
现输出「陆地岛 N 块 / 可走连通块 M 块 → 每座岛内部都走得通 ✔」。
8 个种子 × 2 组参数全部通过，跨 Harrow/BootyBay/GnollWood/LostTemple 模板也全过。

### 新增/修改的文件
- `tools/gen_height.py`：新 `mode_filter` / `clean_regions` / `_multi_dijkstra` / `_backtrack`，
  重写 `carve_ramps` 与 `connectivity_report`；新参数 `--octaves --smooth --level-bias
  --min-island --min-lake --boundary`；默认 freq 1.6 / layers 4 / water 0.30

## 第三轮（15:40 起）：树木分布重做 + 高度层范围 + GUI

### 用户提出的三件事
1. 斜坡先放一放（当前 128/160 全通过、192 偶发 1 例）→ 转做别的
2. **树木分布太集中**
3. **生成时能选悬崖的高度范围** + **要一个选模板/调参数/一键生成的 UI 窗口**

### ① 树木为什么挤成一坨（根因）
老做法 = `fBm 噪声场 → 取一个分位阈值 → 阈值以上的格子全种树`。
噪声的等值线本身是一条连续闭合曲线，**取分位阈值得到的必然是一个大连通块**，
覆盖率一高就糊成一整片实心林（实测：3841 棵树 = **8 片**，最大一片 **3051 格**，
孤立单株 0%）。调 freq/octaves 只能改块的大小，改不了「实心」这件事。

### ② 换成「树丛播种」（tools/add_doodads.py `place_clumps`）
把「每丛多大」和「丛间隔多远」变成两个直接可控的量：
- 丛心候选打分 = `(1-w)·rand + w·森林场·(0.3+0.7·rand)`，**最小间距 = gap_mul × 丛半径**
  逐个贪心接受 → 丛心天然散得开（w = `--clump-bias`，0=均匀铺开，1=强烈偏森林区）
- 每丛株数 `uniform(0.35,1.9)×clump_size`、半径 `lognormal(0,0.32)` → 灌木丛/大树林混着来
- 丛内按 `距离 + 随机抖动` 排序取够株数 → 边缘参差，不是标准圆
- 丛心放不下时**沿林缘向外生长**（维护 frontier 列表，只从"还有空位的林缘格"抽），
  绝不用"随机抽空格"兜底 —— 那个会撒出一堆孤零零的单株，观感更差
- `--scatter` 丛外零星散树（默认 1.5%）

## 第四轮：树林分布算法调研（用户问「图灵斑点算法能不能生成自然树林」）

### 结论：不能。图灵斑图（反应扩散）给的是「规则栅格」，恰好是森林的反面。

用生态学标准指标量化（脚本 `tools/_tmp/forest_patterns.py`，图 `out/_forest_algo_compare.png`）：

| 方案 | 株数 | 最大块 | 平均块 | Clark-Evans R | NN-CV |
|---|---|---|---|---|---|
| ① 泊松随机（基准） | 5514 | 33 | 2.5 | 1.070 | 0.464 |
| ② **图灵斑点**（Gray-Scott f=.035 k=.065） | 492 | 1 | 1.0 | **1.814** | **0.070** |
| ③ 图灵斑点 × 适宜度场 | 219 | 1 | 1.0 | 1.229 | 0.077 |
| ④ 图灵迷纹（f=.022 k=.051） | 42 | 1 | 1.0 | – | – |
| ⑤ 纯 Thomas 簇过程（教科书式） | 4420 | 33 | 2.3 | 1.056 | 0.458 |
| ⑥ 过度自疏（反例） | 2018 | 1 | 1.0 | 1.351 | 0.225 |
| ⑦ **place_clumps（本项目算法）** | 5431 | 103 | 27.3 | **0.790** | 0.439 |
| ⑧ 本生成器真实输出 | 5517 | 204 | 23.5 | **0.796** | 0.477 |

**判据**：`R = 平均最近邻距离 / 泊松期望距离 = r̄/(1/(2√(N/A)))`（Clark & Evans 1954）。
- R=1 完全随机；**R=2.1491 = 完美六边形规则排布（理论上限）**；R→0 最大聚集
- **实测成熟林分 R ≈ 0.76~1.25**（Uholka 原始山毛榉林：上层木 1.03~1.23、中下层 0.76~0.93；
  克罗地亚橡树林 0.89~1.28）→ 天然林落在「随机~略聚集」，下木层明显聚集
- ② 的 R=1.814 逼近理论上限，且 **NN-CV 只有 0.070**（所有最近邻距离几乎相等）
  → 图灵斑图的签名就是"等间距等大小的规则点阵"，视觉上像苗圃/果园/豹纹

**机制原因**：图灵斑图 = 局部激活 + 远距离抑制 → 不稳定性只在一个**固定波长**上增长，
所以全图只有一个特征尺度。生态学里它确实存在，但对应的是**水分受限的干旱植被**
（纳米比亚/澳洲仙女圈、尼日尔虎皮灌丛、日本冷杉波纹）—— 那些恰好也是"均匀铺满整片"的
规则图案。参考文献：Klausmeier 1999 Science；Getzin et al. 2016 PNAS；Meron 2019 Physics Today。

**顺带发现的两件事**：
- **教科书式 Thomas 簇过程（子点独立高斯散布）在格子上不会形成紧凑树丛**（平均块仅 2.3 格）：
  真实树丛是"抢地盘抢出来的密实块"，必须像 `place_clumps` 那样**按距离排序填充最近的格子**，
  而不是各自独立落点
- **自疏过头（hard-core 2.0）也会退回人工林**（R=1.351）：过量最小株距会把聚集度拉到规则端

**结论落到本项目**：现在的 `place_clumps`（R=0.790 / 最大块 204 / 平均块 23.5）已经落在
天然林区间内，**不需要改用图灵斑图**。若要再加自然感，方向是"把图灵机制只用在小尺度"：
局部抑制（树不能长在一起）用图灵那套，大尺度分区继续用无特征尺度的适宜度场 + 簇过程。

## 「应用高度」面板（WE 地形面板那一栏）—— 用户打 60 分后要求补的三项控件

**用户原话**：「应用高度那一栏也做一下，这些用于控制地面隆起，凹陷，凹凸不平等特征」

### 定基准：官方对战图到底长什么样（157 张全量扫描 → `tools/_tmp/analyze_height.py`）
口径：`resid = groundHeight - 该台地(同 layer 4 连通块)内均值`，单位换成 WE 高度（÷4）；
`低频 = resid 的 5x5 均值`（≈ 隆起/凹陷），`高频 = resid - 低频`（≈ 凹凸不平）。
官方典型值：**合计 σ=86.6 / 低频 σ=69.7 / 高频 σ=31.9 / 邻差中位 5.5 / 邻差 p99 89**。
关键发现（`tools/_tmp/hist_height.py`）：**官方 36%~64% 的相邻角点完全等高**，
残差取值多是 4 的倍数 → 官方地形是「大片平坦面 + 1 WE 单位量化的陡坎」，
不是处处连续的坡。GnollWood p10 的邻差中位甚至是 **0**。

### 实现（`gen_height.py`）
```python
lf   = unit_noise(noise_cells(cols, blob), octaves=3)      # 单位标准差场
bell = where(lf>0, lf*raise_amp, lf*lower_amp)             # 上半隆起 / 下半凹陷，幅度可不对称
hf   = unit_noise(noise_cells(cols, grain), octaves=3, gain=0.6)
macro = bell*4                                             # WE 高度 → 原始单位
if ledge>0: macro = round(macro/(ledge*4))*(ledge*4)       # 台阶化（只量化宏观，细颗粒叠在上面）
fine = macro + hf*rough_amp*4
fine = 量化到 height-step=4 原始单位                       # 与 WE 笔刷粒度一致
```
新参数（单位都是 **WE 高度单位 = WE 高度条上的 1 格，一整层 = 128**）：
`--raise 75 / --lower 75 / --rough 12 / --blob 28(格) / --grain 2.5(格) / --ledge 0 /
--height-step 4 / --shade-exag 10`；旧的 `--relief`（单位"层"）保留为兼容别名。
`unit_noise()` 把场归一到零均值+单位标准差，**所以参数值≈实测 σ**，改尺度不会跑偏。
`noise_cells(cols, size_tiles) = cols/size` → 尺寸参数与地图尺寸无关。

### 顺手修掉的三个噪声伪影（都是实测看出来才发现的）
1. **45° 砂纸斜纹**：`value_noise` 用线性插值，格线上留折痕，多八度叠起来就是斜纹。
   → 权重改 **smoothstep（3w²-2w³）**。
2. **规则点阵/棋盘**：格点数与角点数整除时（129 角点配 65 格点）噪声节点正好落在每像素上。
   → 每层**格点相位随机偏移** + `np.mod` 环绕（不再 clip，避免边缘平坦）。
3. **超奈奎斯特混叠**：八度细过一个角点一格就纯是假图案。
   → `fbm()` 里 `if f > min(shape): break`。

### 实测结果（`tools/_tmp/measure_one.py`，128-128 / seed 424242）
| 指标 | 官方典型 | 修改前 | 修改后 |
|---|---|---|---|
| 台地内残差 σ | 86.6 | 8.3 | **75.7** |
| 低频 σ | 69.7 | 7.9 | **70.8** ✔ |
| 高频 σ | 31.9 | 1.5 | **15.5**（仍偏低，见下） |
| 邻差中位 | 5.5 | 0.5 | **5.0** ✔ |
| 邻差 p99 | 89 | 3.0 | 39 |

用户原来那张图之所以像「塑料板」：`fine` 的 `freq*2.5=4` 格 → 最小波长 7.6 格，
**层内低频 σ 只有 7.9、高频 1.5**，等于一块光滑斜面。
⚠️ 高频 σ 到不了 32：官方那 32 主要来自**台阶边缘**（5x5 窗口跨坎时的方差），
靠调大 `--rough` 只会退化回砂纸。要复现就得开 `--ledge 20~30`（默认 0，观感更自然）。
结论：**这个指标是能匹配的，只是官方靠"台阶"拿到高频方差，我们靠"颗粒"。**

## 第六轮：水下隆起 + 平整区域 + 浅水/深水（用户第三条需求）

**用户原话**：「水里也可以有隆起；地图也可有一些区域是平整的，没有隆起凹陷；
水面不仅要有浅水，还需要有深水」

### 先查清水面机制（157 张官方图全量扫，`tools/_tmp/analyze_water.py`）
- **水面世界高度 = 最低陆地层的底线** = `GROUND_ZERO + (layer_min - 2) * 512`，
  也就是浅水层（`water_layer = layer_min - 1`）的**顶面**。默认 layer_min=2 → 8192。
- w3e 的 `waterHeight` 字段里，**低 14 位就是水面原始高度**（0x4000 是边界位），
  所以校验时直接读这个字段即可，不用猜 layer_min。
- **官方地图的水深全是「整层」的倍数**：最常见 1 层（128 WE），其次 2 层（256），少数 4 层。
  → 深水不是渐变，是**下整整一层台阶**，和台地一样。
- **官方地图普遍存在「陆地低于水面」的角点**（有些图高达 7 成，最深 -128 WE）。
  → **「陆地必须高于水面」不是不变量，不要拿它当 bug 修**。

### 实现（`gen_height.py`）
```python
# 平整区域：低频场取最低的 flat 分位 → 核心区起伏乘 0，边缘用 25% 跨度过渡
ff = unit_noise(...) - 0.35 * (1 - code/nlev)      # 偏袒低层（平整区不该长在高台地上）
thr = percentile(ff, flat*100)                     # ⚠️ 是 flat 不是 1-flat（第一版写反了，85% 全平）
wflat = clip((ff - thr) / (span*0.25), 0, 1)
fine *= wflat
# 浅水/深水：离岸距离切
dist = shore_distance(is_water)                    # 多源 BFS，水格到最近陆地的格数
edge = clip(shelf * (1 + 0.7*jit), 0.5, None)      # 岸带宽度带抖动，否则像描边
deep_water = is_water & (dist > edge)
# 水下起伏：按陆地 σ 等比缩放，再按「向上余量」裁
amp_w_raw = min(wrelief * sigma_land, (LAYER_STEP - guard)/2.5)
fine = where(is_water, minimum(fine*(amp_w_raw/sigma_land),
                               cap_sh 或 cap_dp), fine)
layer = where(deep_water, water_layer - deep_layers, ..., layer)
```

### 新参数（GUI「水域与斜坡」面板 + `应用高度」面板）
| 参数 | 默认 | 含义 |
|---|---|---|
| `--flat` | 0.15 | 平整（完全没有隆起/凹陷）区域占陆地的比例 |
| `--flat-size` | 20 | 平整区域的团块尺寸（格） |
| `--shelf` | 3 | 浅水岸带宽度（格），离岸超此即深水 |
| `--deep` | 1 | 深水比浅水再深几层（0 = 关闭深水，全图同一水深） |
| `--water-relief` | 0.5 | 水下起伏 = 陆地起伏 × 该比例 |

### 顺手修掉的两个真 bug
1. **`--layer-min` 根本没生效**：`layer` 是用常量 `LAYER_ZERO` 拼的，不是 `layer_min`，
   所以调 `--layer-min` 只改了层数、没改地形高度（两处：主赋值 + despeckle 块）。
2. **`waterHeight` 写死 8192**：一旦 `--layer-min` 抬高（如 6），水面会落到地形下面，
   整张图一滴水都看不到。改成 `plane_raw = GROUND_ZERO + (layer_min - LAYER_ZERO) * LAYER_STEP`。
   → 实测 layer-min=6 时水面自动变 10240（WE 512），零个水角点冒到水面以上 ✔

### 新工具 `tools/inspect_water.py`（常驻，取代临时版 check_water.py）

- 死条件：带 0x40 水标记的角点世界高度必须 < 水面（必须为 0）
- 输出：水深分位 / 按 layer 分档 / 同层水深 σ（水下起伏）/ 离岸距离分布

## 第七轮：用户问「近战兵种 vs 悬崖」/「有没有算法生成山体」的答疑（未改代码）

### 用户担心的事：悬崖太多不利于近战兵种
**不完全成立，得先把「高度」和「悬崖」拆开**（这是本项目最容易搞混的一点）：
- **悬崖只由 `layer` 相邻差异产生**，且必须是整数层的落差。同一 `layer` 内部的
  `--raise/--lower/--rough`（层内精细起伏）**永远不会变成悬崖**，只是观感。
- `max-jump` 限制的是**相邻角点的层数差**（含地形写的限制），不是精细起伏的梯度。
- 高度档望洋：多层层数 → 多层相邻差异 → 多层悬崖。这就是 `--layer-min/layer-max` 的作用。

### 上 Herbrand调整建议（推荐组合）
| 参数 | 推荐值 | 作用 |
|---|---|---|
| `--layer-max` | 压低到 `layer-min + 1`（= 只有 2 级 Terre） | 立体层数从 4 压到 2，悬崖总数大概降到原来的 1/4 |
| `--level-bias` | 2.0 → **3.0** | 幂次党 forestall 对取值的分布，让**最低层占更大的面积**（ protocols 近战兵团能锁开的连续地面变大） |
| `--flat` | 0.15 → **0.30** | 平整区域翻倍，团队遭遇战能找到大面积水平地面 |
| `--max-jump` | **1** | 明令禁止 2 层崖，只允许 1 层台阶，配合 `--ramp-force 1` 走lus:6.4 |
> ⚠️ `--layers 2` 是前提，否则地图上每一个角落都会被 repetitions 成 drawImage 的碎片画商量 | 上面两个参数的值是配合 `--layers 2` 的，**单独用会非常单调**。

### 现有控制手段盘点（回答「有没有参数可调」）
- ** 大/third尺度（地形成形）**：`--freq` / `--octaves` / `--layer-min` / `--layer-max` / `--level-bias` / `--boundary`
- ** 精细起伏**：`--raise` / `--lower` / `--rough` / `--blob` / `--grain` / `--ledge` / `--height-step`
- ** 形态/清洗**：`--smooth` / `--min-plateau` / `--min-island` / `--min-lake` / `--max-jump`
- ** 斜坡/连通**：`--ramps` / `--ramp-run` / `--ramp-force`
- ✅ **上面这套已经覆盖用户担心的所有东西**（除了「限制开放面积」这种数学上不存在的需求）

### 用户追的第二个问题：「有没有算法生成山体？不能直接调控每个点的高度坡度吧？」
**答**.：
1. **能写但不能编**：我们本来就各理各理地写 w3e（16641 个 lane 全部是接缝可写的），
   **但手动 bad齿ely工作是不存在的**（那是 WE 自己刷地形）。
2. 实际做的是 **「统计参数 + 逐点硬性约束」**：参数决定形势，然后逐点施加硬规则
   （水必须在水面下、斜坡几何必须正确、平整区必须为 0、相邻层差 ≤ max-jump、层数必须在 [min,max]）。
   **「间接但精确」**，支持范围忍者：约束是 100% 强制的，不是概率。
3. 查了：**没有高度图导入接口**（`mask` 只是统计量），**没有斜率限制器**
   （`np.gradient` 只用在预览 hillshade 上，`max-jump` 只管层不管梯度）→ 这两个是**明确的、可加的功能**，目前没有。

### 算法谱系调研（没改代码，纯调研）
| 算法 | 做什么 | 对本项目的价值 | 成本 |
|---|---|---|---|
| fBm 值噪声（现状） | 统计自相似起伏 | 已经是 Γ 到的 | — |
| **Ridged multifractal**（Musgrave） | `1-\|noise\|` 反复叠加 → **山脊线网络** | ⭐ 最像「山脉」given cost | 便宜，几行 |
| **域扭曲 domain warping** | 用噪声去扭曲另一层噪声的坐标 | ⭐ 让走向变自然，撤底的非线性 | 最便宜 |
| 热力侵蚀 thermal / talus | 超过临界角的坡自动坍塌抹平 | 与「近战友好」的**斜率限制**直接对应 | 中 |
| 水力侵蚀 hydraulic（pipe model） | 水流冲刷 → 河谷/冲沟 | 真实感最强 | 中大（128² 还行） |
| 基于草图的特征合成（Hnaidi 2010 等） | 用户画脊线 → 算法生成地形 | 与 GUI 思路契合 | 大（要写交互） |
⚠️ **项目特有陷阱**：前期实测结论是「官方对战图 = 大片平坦面 + 1 WE 单位量化的陡坎，
**不是**连续山坡」。所以物理侵蚀生成的平滑河谷**反而更不像官方图**。
→ 真要加，性价比最高的是 **ridged multifractal / 域扭曲 + 较强的 `--ledge` 台阶化**，
而不是完整水力侵蚀。

### 结论吐露给用户
- 如果目标是「**近山一般 yaşan**」→ 加 ridged multifractal 或域扭曲（成本很低）
- 如果目标是「**近战友好**」→ 加的是**斜率限制器**（限制层内最大梯度），不是山体算法
- 这两件事是**两个不同的需求**，别指望一个改动同时解决
