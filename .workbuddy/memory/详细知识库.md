# automap 详细知识库（MEMORY.md 的展开版）

> 本文件是 `MEMORY.md` 的详细备份，**不自动注入**。需要查细节时再读。
> MEMORY.md 只保留「绝不重犯的坑 + 常用旋钮」。本文件保留全部实测事实。

## 一、项目边界
- 类红警 2 的 WC3 随机地图生成器：运行 → 随机地形 → 存 .w3x → WE 里手动改。核心是**操作 MPQ 内的 war3map 二进制文件**。
- `automap/` = 本项目（零外部依赖，自带 `bin/MPQEditor.exe`）；`mapgen/` 是另一项目，互不引用。
- 分层开发，每层由用户在 WE 目测验收后才进下一层：① 地形+装饰物 ② 中立建筑 ③ 野怪单位。

## 二、生成方式本质
**复制模板地图 + 只覆盖 2 个文件**。模板 = `template/*.w3m`。只有 `war3map.w3e`（地形）和
`war3map.doo`（装饰物/树）被替换，其余 14 个文件与模板逐字节相同。
- `war3mapUnits.doo` 仍是模板残留（sloc×4、ngol×12、商店、100 野怪），坐标与新地形对不上 → 层 2/3 必须整文件重写。
- `wpm`/`shd`/`Map.blp`/`mmp`/`j`/`w3i`：WE 保存时会重算 wpm/shd/blp，**但不会重算 units/mmp/w3i**。

### 模板表
| 文件 | w3i | units.doo | 备注 |
|---|---|---|---|
| 64/96/128/160/192 `.w3m` | v18 | v7.9 n=1 | ✅ 主力，1.27a 原生 |
| 224/256 `.w3x` | **v25** | **v8.11** | ⚠️ 1.31+ 产物，1.27a 大概率读不了，别用 |

全部完全平坦（gh=8192、layer=2）、0 装饰物、flags 0x80 全 0、纹理集 `L`。唯一残留 = 1 条 sloc（owner=0）。
体检：`tools/inspect_template.py`。⚠️ `template/*.w3m` 不可再生，动之前必须问。

## 三、二进制格式事实（实测反推）
- **w3e v11**：7 字节/角点；`world = (gh-8192+(layer-2)*512)/4`；层零位 2，每层 512 原始 = 128 WE，layer=15 崩溃。
- flags 高 4 位：`0x10` ramp / `0x20` blight / `0x40` water / `0x80` 边界外（**水不是 0x80**）。
- **`0x80`(flags) 与 `0x4000`(waterHeight) 是同一「边界外」概念的两份标记**，必须一致。带这两位的瓦片可走率 0%。
  `--boundary`: `ring`(默认，只留最外一圈) / `none` / `keep`。带 ramp(0x10) 的悬崖瓦片可走率 79% ✔。
- **war3map.doo**："W3do" v7.9，定长 42 字节/条 + 尾 8 字节。
  id(4) var(4) x,y,z(12) rot(4) scale×3(12) flags(1) life(1) itemTable(4)。z = 该格四角 WE 高度均值（7215 棵树误差 0.000）。
- **war3mapUnits.doo**：v7.9，**变长记录 91~139 字节** → 解析用「扫记录开头 + 固定前缀偏移」。
  偏移（p=起点）：p+0 id / p+4 var / p+8 x,y,z / p+20 angle / p+24 scale×3 / p+36 flags / p+37 owner /
  p+43 hp / p+47 mana / p+51 掉落集合数 → p+55 起 [n(4)+n×(itemId4,chance4)] → gold / targetAcq / heroLevel / n_inv / n_ab → 尾 16 字节。
  owner：**12=中立敌对(野怪)**、15=中立被动(金矿/商店)、0..3=玩家槽。出生点 `sloc`，金矿 `ngol`。
- **units 可从零手写**：`pack("<4sIII","W3do",7,9,n) + recs + tail`；空文件 24 字节（尾 8 = `ffffffff6d000000`）。
  验证：`tools/_tmp/utest/test_write_units.py`。
- **wpm**：magic **"MP3W"**，v1，4 倍分辨率。64=可走地面，206/202=边界外，8/10=水。生成器不改 wpm。
- 世界坐标：瓦片中心 `x=(i+0.5)*128-W*64`，`y=(j+0.5)*128-H*64`。**w3e 文件行序自下而上**（图像行 cy=0 写到文件行 rows-1）。

## 四、🔴 核心原则：挡路的只有「层差」
315 张官方图实测（`tools/_tmp/check_gh_deviation.py`、`check_slope_walkable.py`）：
1. 层内 gh 偏离无 ±512 限制：43% 角点层内偏移 > 1 层，最大 **6144 原始 = 1536 WE = 12 层**；
   存在全图 1 个 layer 却有上千 WE 落差的官方图。
2. 层内坡度不产生不可通行：四角同层瓦片内高差 8→190 WE，可走率仅 87.8%→70.4%，**无塌到 0 的阈值**。
   对照：层差=1 且无 ramp → **0%**。
→ **layer 差异 = 悬崖 = 挡路；层内起伏 = 不挡路，只是观感。**

## 五、🔴🔴 世界高度下限 -256 WE（WE 闪退根因）
45 张官方图（`tools/inspect_world_range.py`）：**最低角点恰好卡在 -256.0**，最高 1536.0。
-256 正是 **layer 0 的世界基准 `(0-2)*128`** → 硬地板。跌破 → WE 能打开、能显示，**但一编辑地形就闪退**。
- 谁会跌破：① 单层模式（layer 常数 2，落差全在 gh 里）；② 悬崖模式深水（`relief_w = fine*k` 只裁了向上余量、没下限）。
- 修法已实现但默认关（`--world-clamp 0`）。
- 🔴 **2026-09-16 用户拍板：不修**。开了钳制**仍然闪退**，且「会导致一些坡度形态被限制」（削平最深水底）。
  所以默认完全不干预地形，只在越界时打印一行警告。别再拿这个去改地形。
- ⚠️ 次要越界（未修，判断无害）：`d_gh` 我们 237 vs 官方 max 162.5；但 `d_world` 我们 344 < 官方 408.8 ✔
  （官方把落差放在 layer 里、我们放在 gh 里，只看 d_world 才公平）。

## 六、三步式生成（方案书 `doc/三步地形生成方案.md` §12）
① 地形基底（初始地面 + 山脉抬升 → 连续高度场 H，水面切割）→ ② 悬崖（可选）→ ③ 树木（可选）。
- **两模式共用同一个连续场 H，编码公式统一**：`world = fine/4 + (layer-2)*128 = H_we + (plane_layer-2)*128`。
  台地靠 layer 抬起来，`gh` 自动少掉 128k，台阶面照旧平滑。
- **`--cliffs` 默认 0**。`--cliffs 1` = **只在若干小块区域**生成悬崖：
  `cliff_mask()`（低频场取高分位 → 天然几大块；众数滤波；清碎块；**离水 32 WE 内不选**；`solid` 参数做填洞；
  遮罩距地图边留 3 格 `mg=3`）
  → `apply_terraces()`：mask 内 `Hgap + 128k` / 层号 `layer_min+k`；mask 外紧贴一圈羽化拉平到 `Hgap`/`layer_min`
  → **边界落差严格 = 128k = 层差**（WE 渲崖壁的**唯一**不变量）。
  `_lipschitz_levels()`：台地级数场约束成「相邻格（遮罩外视为 0 级）最多差 1 级」，只降不升
  → 遮罩边界落差恒 ≤1 级，斜坡能跨、地面能走（修「上不去的孤岛」）。
  旋钮 `--cliff-area 0.15 / --cliff-size 26 / --cliff-layers 3 / --cliff-feather 4`；
  `cliff_layers` 被 `max-jump`、`MAX_LAYER-layer_min`、`layer_max-layer_min` 三重夹住。
- **深浅水一律只靠 gh 落差表达、不换 layer**（换 layer 会在水下多出崖壁、浅水处可能露出来）。
- `--base`（deep -384 / shallow -128 / **land** 0；`flat` 已改名 `land`）一旦指定 → **水面恒为 0、`--water` 失效**。
  实测水域占比：deep 95% / shallow 70%（uplift 220）。语义：
  `deep` 正常水域 / `shallow` **一滴深水都没有**（整片水域乘统一系数压到 `--shelf-depth`）/
  `land` **一滴水都没有**（整块抬到水面之上）。实现 `apply_base_semantics()`，
  在叠加「应用高度」**前后各调一次**（起伏会把水底推深、把陆地压回水下）。都**保形状**，不硬砍。
- 山脉算法 `--mountain`：`fbm`（默认）/ `ridged`（山脊线）/ `warped`（域扭曲）。
  `value_noise` 支持 `warp` 位移场（单位 = 格点坐标，1 像素 = cells/cols 格点单位）。
- `--max-relief`（默认 512 WE）用 **tanh 软裁剪**，不切平顶。
- 单层模式「平整区域」整块向**陆地平均高度**压平（压向 0 会把平整区按到水面上）。
- ⚠️ **量化陷阱（真 bug）**：hstep 量化会把水陆分界附近的角点四舍五入到水面错误一侧。
  判据必须换算成**世界高度**：`layer_over = (layer-plane_layer)*512`，
  水角点 `fine ≤ -layer_over - hstep`、陆地角点 `fine ≥ -layer_over + hstep`。
  **只判 `fine < 0` 是错的** —— 台地角点层号比水面层高 k 级，`fine` 要低到 `-512k` 才真沉进水里。
- 单层模式平整区压平逻辑在 `fine` 与 `H_we` 上各作用一次；`is_water` 在加完细节后要重算一次。
- `--octaves` / `--level-bias` / `--min-plateau` / `--shelf` / `--deep` 已**失效**（保留兼容）。

## 七、斜坡（ramp）—— 2026-09-16 大修
### 几何模型
- WE 里斜坡 = 「**垂直于崖壁 3 条角点线（2 个瓦片厚）的带**」，层差恒为 1。
- `_stamp_ramp` 用 5 条角点线模型：`want=(out_lo,lo),(far_lo,lo),(shared,lo),(far_hi,hi),(out_hi,hi)`；
  `band=(far_lo,shared,far_hi)` 这 3 条线打 ramp 位。
- 瓦片构成 = 四角全低基地 + 2低2高台阶。
- `ramp_report()` 判据：四角全带 ramp 位的瓦片，其四角 layer 必须 (a) 全同层 或 (b) 恰好差 1 级台阶（2低2高）；
  否则 `other+=1` → 非法。
- 别用「两侧必须紧挨平地」的判据；斜坡连通用「多源 Dijkstra 求台地邻接图 → Kruskal 生成树 → 沿路径铺 0x10」。

### 🔴 坡面高度：必须贴住两侧台地，**绝不能按到层基准线**（用户核心反馈）
- 症状：「斜率太大、凹陷到地心」—— 坡面沉下去 400~500 WE 的深沟。
- 根因：把坡带角点的 `fine` 清零（`fine = where(band, 0, fine)`）。清零 = 按到**层基准线**，
  而层基准线离台地面差一个 `Hgap`（几十~几百 WE）→ 深沟。
- 修法（现行）：`fill_band_fine(fine, layer, band, radius=8, win=4)` ——
  ① **局部 PCA**：取该角点 `win`(4) 格邻域内的坡带角点，主轴 = 坡带切线，法线 = 主轴转 90°；
  ② 用「层号高的角点在法线正侧」定朝向，低层线取 −法线、高层线取 +法线；
  ③ 把方向**吸附到 8 邻域里的一个**，沿**严格直线**逐格找**同层号**非坡带角点，命中即取该值；
  ④ 找不到（整条坡带同层 / 严格方向上够不着）→ 退化成半径内任意同层号角点平均 → 盒式模糊兜底。
- 结果：坡带低层线 = 下台地地面高度、高层线 = 上台地地面高度，**逐角点精确贴合**。
- ⚠️ 三个不能回退的点：
  **① 不能不分层号地邻域平均**（会拿两台地中间值，坡面中段鼓包）；
  **② 不能用「点积 ≥ 阈值」代替方向吸附** —— 坡带中间那条线的正对面就是坡带自己，
  最先命中的同层号地面往往是**斜向的切向地面**（seed=777 站点 #5 中间线被拽低 42 WE）；
  **③ 不能整条坡带连通簇只算一根法线** —— 多条斜坡会连成一片（`验收_局部悬崖` 有一块
  21 瓦片），簇级法线对不上（站点 #16 偏差 85~127 WE）。改局部窗口后同一站点变成精确复制。
- 实测（seed=777 探针，`tools/_tmp/ramp_slope_probe.py`）：
  清零版坡面最低 **1~256 WE**（周围 550~620）→ 站点 #5 下探 **-63 → -26 WE**，
  剖面逐角点等于两侧台地（r56=r57=r58 低台地、r59=r60 高台地）。与官方 BootyBay 一致。
- 全局改名：`zero_fine` → `ramp_band`（语义已从「清零」变「坡带标记」）。

### 双遍刻斜坡 + 合法性守卫（消灭非法瓦片）
第一遍 `carve_ramps` → `merge_orphan_flats` → 用**最终** `is_water` 复查 → 第二遍 `carve_ramps(prev_ramps=...)` 补刻。
- `carve_ramps(prev_ramps=)`：避免第二遍以为「地图无斜坡」而在旧斜坡上平移重刻造成重叠。
  ⚠️ 参数别叫 `prev` —— 会被内部 `_multi_dijkstra` 返回的同名 `prev` 覆盖（改 `_bfs_prev`）。
- `_stamp_ramp` 既有占位守卫：落点处 `ramp[rr,cc]` 已占用且层位 ≠ 目标 → 放弃该落点。
- `_stamp_would_be_legal()`：试算盖下去后邻域会不会留下「四角全带 ramp 位但层位非法」的瓦片，不合格换落点。
- `carve_ramps` 的 `done` 集合：第二遍用「平地|既有斜坡瓦片」算可走连通块，已连通的台地对跳过（斜坡数不再翻倍）。
  ⚠️ `ramp`/`ramp_band` 赋值必须提到 `done` 块**之前**，否则 `UnboundLocalError`。

### 四级连通性硬保证（别退回只靠 carve_ramps）
1. `carve_ramps` + `merge_orphan_flats`；
2. 用**最终** `is_water` 复查 → 还断着就再扫一遍候选崖段**补刻**（第一遍用过的崖段已标掉）；
3. `drop_unreachable_terraces()`：够不着的台地整块撤掉（layer 拉回水面层 + 高度减 `128×层差`）；
4. `drill_ramps_for_connectivity()`：**0-1 BFS**（可走瓦片代价 0 / 崖壁代价 1）从每座岛最大可走块出发，
   找通往其余可走块的最便宜路径，把路径上崖壁瓦片四角都打 `0x10` → **斜坡瓦片按定义可走 → 必然接通**。
   只从 `spread==1` 的崖壁开坡；每盖一格用 `_illegal_ramp_count` 试算，会产生非法斜坡瓦片则撤销；
   返回 `(ramp, opened, reverted)`，并打印「放弃 N 处」。
5. 之后再补一轮 `drop_unreachable_terraces`（`n_drop2`，处理「挡路只剩 2 级崖壁、1 级斜坡跨不过去」的台地）。

### 瓦片级数组降维陷阱
`_tile_derivatives` / `_components` 出来的 `spread/dry/walk/wlab/ilab` 全是 **(rows-1, cols-1)** 瓦片级，
不能再做四角与运算（`m[:-1,:-1] & m[:-1,1:] ...`）—— 会静默错位一格，症状是「明明有孤岛却说没有」。

## 八、噪声 `value_noise` 三个伪影修复（别退回去）
① 插值权重必须 smoothstep(3w²-2w³)，线性会在格线留折痕 → 45° 砂纸斜纹；
② 格点相位随机偏移 + `np.mod` 环绕（129 角点配 65 格点会出规则点阵）；
③ `fbm()` 里八度细过「一角点一格」就 break。

## 九、树木分布（`place_clumps`）
**别用「噪声场取分位阈值」撒树** —— 等值线闭合，必然糊成整片实心林（3841 棵 = 8 片，最大 3051 格）。
现用**树丛播种**：丛心 = 森林场×随机抖动打分 + 最小间距 `--clump-gap × 丛半径` 贪心接受；
株数/半径抖动；丛内按「距离+抖动」排序；株数不够时**沿林缘生长**（维护 frontier），不许用「随机抽空格」兜底。
最大块 3051 → ~200 格。旋钮 `--density / --clump-size / --clump-radius / --clump-gap / --clump-bias / --scatter`；
指标 `blob_stats()`。
⚠️ `np.mgrid[y0:y1,x0:x1]` 是 (nj,ni)，`elig[x0:x1,y0:y1]` 是 (ni,nj)；随机半径会 broadcast 炸。

## 十、应用高度（隆起/凹陷/凹凸/台阶）
单位 = **WE 高度单位（1 层 = 128）**；`unit_noise()` 归一到零均值单位标准差 → **参数值 ≈ 实测 σ**。
`--raise/--lower` 75/75、`--rough` 12、`--blob` 28、`--grain` 2.5、`--ledge` 0、`--height-step` 4（= 1 WE）。
**官方基准**（157 张）：合计 σ 86.6 / 低频 69.7 / 高频 31.9 / 邻差中位 5.5 / p99 89。
36~64% 相邻角点完全等高 → 官方 = 「大片平坦面 + 1 WE 量化的陡坎」。
⚠️ 高频 σ=32 拿「颗粒」换不来（只会变砂纸），来自**台阶边缘**，需 `--ledge 20~30`。
预览图叠 `hillshade()`（exag=10 只影响预览），否则纯色块看不出起伏。

## 十一、水面
- 水面世界高度 = `GROUND_ZERO + (layer_min-2)*512`；w3e `waterHeight` **低 14 位 = 水面原始高度，0x4000 = 边界位**
  → 读这个字段，别靠 layer_min 推算，别用常量 8192。
- 官方水深全是**整层倍数**（1/2/4 层），深水 = 下整层台阶，不是渐变。
- 🔴 官方 38 张有水图实测：逐角点水深 **p50 基本就是 128 / 256 WE**，最浅也只到 66~90 WE（岸线毛边），
  81~98% 恰好是 128 的整数倍。**结构上水区 `layer` 恒比周围陆地低 1~2 个整层**
  （LostTemple 水 0/1、陆 1~5；SwampOfSorrows 水 0/1、陆 2~8），`gh` 基本不动。
  **没有一张官方图是「水陆同层、只靠 gh 下沉」表达水的。**
  ⚠️ 我们的 `--base shallow` 生成的水是**同层 + 最深仅 96 WE（中位 27）**，落在官方从不出现的深度区间，
  用户实测在 WE 里**看不到水、像纯陆地** → 高度怀疑 WE 按 layer 判水。
- 官方 wpm 只有 6 种取值：64(陆)/72(浅于~80WE 的浅水)/8(1档深水)/10(2档深水)/202/206(边界不可走)。
  202/206/10 带 `0x02` 位 → 疑似不可通行；8 不带 → 1 档浅水可能可走、2 档深水不可走。
  `0x40` 可走标志随深度衰减：≤80 WE ~100%，104 WE 40%，128 WE 33%。
- ⚠️ **官方普遍存在「陆地低于水面」的角点**（最高 7 成，最深 -128 WE）—— 不是 bug，别修。
- 参数：`--flat` 0.15 / `--flat-size` 20 / `--shelf` 3 / `--deep` 1 / `--water-relief` 0.5。
- 实现：平整区取低频场**最低** `flat` 分位（写反成 `1-flat` 会让 85% 全变平）；
  岸带 `edge = clip(shelf*(1+0.7*抖动),0.5,None)`（**必须抖动**，否则像描边）；
  水下起伏向上余量 `LAYER_STEP - LAYER_STEP/4` = 384。
- `tools/inspect_water.py`（常驻）校验：带 0x40 的角点世界高度必须 < 水面。
- 预览图**水面也要叠柔和山体阴影** `sh_soft`。

### 两个真 bug（教训）
1. `--layer-min` 曾不生效：`layer` 用常量 `LAYER_ZERO` 拼 → 主赋值和 despeckle 块**两处都要用 layer_min**。
2. `waterHeight` 曾写死 8192：`--layer-min` 一抬高整张图没水 → 必须 `plane_raw = GROUND_ZERO + (layer_min-LAYER_ZERO)*LAYER_STEP`。

## 十三、工程约定
- **编码：管道一律 UTF-8**。`✔ ✘` 不在 GBK 里 → cp936 子进程 `UnicodeEncodeError`，
  且崩在 subprocess 读线程里导致 `r.stdout` 变 None，报错完全指不到真因。
  约定：每脚本开头 `force_utf8_stdout()`；`subprocess.run(text=True)` 必须显式 `encoding="utf-8", errors="replace"`；
  random_map 统一走 `run_child()` + `CHILD_ENV = {PYTHONIOENCODING:"utf-8", PYTHONUTF8:"1"}`；
  读 `r.stdout` 前 `or ""`。排查需 `env -u PYTHONUTF8 -u PYTHONIOENCODING` 复现。
- **临时目录**：`shutil.rmtree`/`os.remove` 在沙箱被删除保护拦截（症状 = 地图已生成但退出码 1）。
  统一用 `make_tmp(name)` / `drop_tmp(tmp)`（父目录尽力清空 + 本次唯一子目录 `r<pid>_<ms>`，
  清理包在 `except BaseException`）。
- **备份**：`random_map.py` 已复制模板到 `out/`，子工具再备份是垃圾（曾堆到 1183 个文件）。
  两个子步骤都传 `--no-backup`；单跑时只保留同名最近 100 个 `.bak`。清空用 `find backups -type f -delete`。
- **删除不要问**（用户明确要求）：`tools/_tmp/` 临时文件、`out/` 下自产中间产物与预览图、`backups/` 自动备份，直接删。
  **唯一例外 `template/*.w3m`**。
- 工作方式：先分析 → 用户确认 → 才改代码；格式一律实测反推，以「解析到文件尾零误差」为验证标准。

### 官方图的形态（渲染出来的事实）
`_tmp/render_official_trees.py` 把树掩码画成 PNG：
- **(2)Harrow**：贴着地图边框一圈**粗林带**（有缺口）+ 内部零散块 + 大量单株。
- **(4)LostTemple**：沿地图边与各基地外缘的**粗林带**，四折对称，边界参差。
- **(6)GnollWood**：贴水岸 / 边界的林块。
→ **树的分布强烈依赖地形边界**，不是均匀撒。这是「斑点感」的根因。

### 实现（`tools/add_doodads.py`）
| 函数 | 职责 |
|---|---|
| `dist_transform(mask, maxd)` | 到 mask 边界的 8 邻接距离（迭代膨胀，不引 scipy） |
| `build_forest_field` | 森林场 = `norm01(edge_forest × band × 沿边噪声 + (1-edge_forest) × fbm)`；`band = exp(-d_border/edge_band)` |
| `build_fine_field` | `fbm(freq×6, octaves=2)`，给生长边权当抖动 |
| `grow_region` | 堆 Dijkstra；`step = (1+1.6(1-field)) × (1+3.0(fine-0.5)) × (1+0.45×rand)`；弹出即落子 |
| `place_forests` | 打分 `field² × rand` 挑核；`sep = 2.2×2×sqrt(2.2×med/π)`；`ri = ceil(sqrt(2.2×med/π))+2`；`sz = clamp(med×lognormal(σ=0.5), 6, 2.2×med)` |
| `place_groves` | `quota = max(3, med×lognormal(σ=0.85))`；`rad = radius×sqrt(quota/med)` 上限 20；随机取向椭圆（`ecc = clamp(exp(N(0,0.32)),0.5,2)`）+ 噪边；禁区 `d_an ≤ 2rad+gap`；初始禁区由 `dist_transform(~taken) ≤ 2×radius+gap` |
| `place_scatter` | 按 `(1-field)` 加权抽自由格 |
| `grow_along_edge` | 沿林缘小块生长（`chunk=8`）补足株数 |
| `_ellipse_drop` | 椭圆距离 / 椭圆距离+噪声 的**唯一出口**（统一 `mgrid[x范围, y范围]`） |

### 踩过的坑（量化诊断）
| 坑 | 症状 | 修法 |
|---|---|---|
| 核间距按中位尺寸算 | 7 核粘成 897 格巨块 | 按 `2.2×中位` 算 |
| 把核间距当离边余量 | 128 图放不下第二个核 | 边距单独算 |
| `grow_region` 局部择优邻居 | 顺林带长成蛇，3 核串成 1572 格 | 改加权最短路 |
| `mgrid` 轴向搞反（禁区用 `[y,x]`） | 禁区转置圈错，95 丛 → 9 块 | 统一 `[x,y]` + 单一出口函数 |
| 丛间距只按半径留 | 半径 3 的丛中心隔 5.7 必相接 → 连成网 | `2×半径+空隙` |
| 无细噪声 | Dijkstra 结果是**完美菱形**（L1 球） | `fine_amp=3.0` |
| 株数不够靠「沿林缘补生」 | 把大林越喂越大 | `place_groves` 改成不设丛数上限、撒够为止 |

### 实现要点
- `_blob_labels` 4 连通标记 → `n_blob / max_sz / lone / n_big / frac_big / ratio`；
- `_shift_or` 不环绕的平移 OR；`_neigh_any(mask, r)` = **从全零 OR 位移副本、永不含 (0,0)**
  →「这一格的 r 邻域里有没有**别的** True」；
- `_dist_to(mask)` = 多源 BFS 膨胀写法（每轮 `_neigh_any(cur,1) & ~cur`），
  到 mask 的 **8 邻接（Chebyshev）** 距离，不引 scipy、不写 Python 队列。

### 🔴 `dilate` 含自身（静默错误，踩过两次）
标准膨胀语义是 `mask ∪ 邻域`。
- `t & ~dilate(t,1)` → tree 格恒 False → **孤立率恒 0**；
- `t & ~(dilate(t,1) & ~t)` → **恒 1**。

两种写法都**不报错**，只是安静地输出「43 张官方图孤立率全是 0 / 全是 1」这种荒谬统计，
据此误判过一轮算法方向。所以：
1. 指标只能有一份实现（`forest_metrics`），四个脚本全调它；
2. `tools/_tmp/test_forest_metrics.py` 用 31 项手工可算的小例子把语义钉死
   （单点/正交相邻/对角相邻/相距 3 格/5×5 方块/阈值边界/切比雪夫距离/空 mask）。
