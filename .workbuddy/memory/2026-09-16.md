## 三步式地形生成方案书（已出，**未实现**，等用户确认）

用户提出把地图生成拆成三步：
1. 选初始地面（深水 / 浅水 / 平地）+ 山脉算法抬升 → 高处天然成陆地
2. 可选：按高度范围生成悬崖（= 现有功能）
3. 可选：森林算法撒树（= 现有功能）

方案书写在 **`doc/三步地形生成方案.md`**（新建目录）。核心内容：

### 统一模型（方案书的骨架）
内部一律用「**相对水面的高度**」（水面 = 0，单位 WE）：
```python
base = {"deep": -384, "shallow": -128, "flat": 0}[base_mode]   # WE，负 = 水下
H    = base + uplift * mountain_field(...)                      # 零均值单位标准差
is_water = H < 0.0 ;  depth = -H
```
写文件时再映射：`gh = GROUND_ZERO + H*4`（4 原始单位 = 1 WE），`waterHeight` 字段 = GROUND_ZERO。

### 关键抽象：悬崖 = 量化
- `cliffs=0`（单层）：`layer` 全图常数，落差全放 `gh` → **零悬崖**
- `cliffs=1`：把 H 量化成整层台阶 → 台地 + 垂直崖壁 + 刻斜坡（复用现有全部代码）

### 单层模式下水要改（重要）
现在代码把水角点强行设成 `water_layer = layer_min - 1` → **岸边永远有一整层落差**。
要做「平滑入水」必须让水角点**保持和陆地同 layer，只降 gh**（水靠 waterHeight 字段
与世界高度比较渲染，同层降 gh 一样出水）。这是 P2 的核心改动点。

### 我对用户原方案的三点修正（写进方案书第 7 节）
1. 「深水/浅水/平地」别做成离散三选一 → 给连续的 `--base-level`，三个只是预设
2. 「有水也能产生陆地」的副作用是**水域占比不再精确可控** → 保留占比模式用分位数反解水面
3. 「按高度范围生成悬崖」本质就是**量化** → 直接做成后处理开关，不是另一套生成逻辑

### 幅度上限
`gh` 是 u16，`dev = gh - 8192`。官方实测 ±8192 都安全（最大 6144）。
方案里默认 `--max-relief 512`（WE，= 2048 原始单位 = 4 层落差的连续起伏），可调到 1024～1536。

### 实现计划 P1~P7
P1 抽连续高度场 → P2 单层模式 → P3 `--cliffs` 开关 → P4 山脉算法(ridged/warped)
→ P5 `--trees` 开关 → P6 GUI 三步面板 → P7 验证。
主线 P1→P2→P3；P4/P5/P6 可并行。

### 最大的风险（必须用户验证）
**我们生成的单层大振幅图还没在 WE 里打开过**。官方图有铁证（存在全图 1 层、偏移 6144
的图），但自己出的图必须让用户看一眼。P2 做完要出样图。

## 三步式方案已实现（2026-09-16 下午，P1~P7 全部完成）

改动：`gen_height.py`（P1-P4 + 单层水处理）、`random_map.py`（P5 `--trees` + 参数透传）、

### 实现时的三个设计决策（方案书没写透的地方）
1. `--base` 一旦指定 → 水面恒为 0、`--water` 失效。否则 base 在占比模式下只是纯垂直
   平移（percentile 平移不变量），完全不起作用 —— 占比模式里三个 base 预设出图完全相同。
2. 单层模式不做「深水降层」（方案书没明说）：layer 一动水下就有崖壁，浅水处可能露出；
   深浅水改按实际深度 `--shelf-depth` 切。
3. 单层模式的「平整区域」向**陆地平均高度**压平，不能压向 0（会把平整区按到水面上）。

### P7 验收抓到的一个真 bug
高度量化（4 原始单位一档）会把水陆分界附近的角点四舍五入到水面的错误一侧 →
`inspect_water.py` 报「水面以上的水角点 16~22 个 ✘ 水会画穿」。
修复：量化**之后**强制 `水角点 fine ≤ -hstep / 陆地角点 ≥ 0`（必须在量化后做，
且两边都得是 hstep 的倍数才不会再被挪动）。修复后 4 种组合 + 25 张图全部 0 违规。

### 验收结果
1. `--cliffs 0`：层值全图唯一、斜坡 0、连通 ✔（5 尺寸 × 5 种子 + 4 种算法/初始地面）。
2. `--cliffs 1` 同 seed：与 `git show HEAD:tools/gen_height.py` 旧版**逐字节一致**（md5 相同）。
3. `inspect_water.py` 0 违规。
4. GUI 全链路（起服务 → POST /api/generate）：无悬崖 / 悬崖两模式都跑通，三步面板正常。

### 遗留
- `value_noise` 改成 `grid[y0, x0]` 双二维 fancy indexing（支持 warp 的位移场），
  数学上与旧写法等价，回归已确认。
- **单层 + 大振幅 gh 在 WE 里的渲染观感仍未确认**，样图在 `out/样图_*.w3x`（4 张：丘陵 fbm /
  山脉 ridged / 群岛 deep / 对战图 cliffs）。

## 🔴 定位并修复「WE 里微调地形就闪退」（同日，重要）

用户报：生成的地图用 WE 打开后微调地形直接闪退。

**根因**：地形**世界高度跌破 -256 WE**。
写了个包络对比工具（已转正为 `tools/inspect_world_range.py`）：把生成图和 `../Maps` 下
45 张官方图放同一套指标下比。结果：
- 官方图 world_min **最低恰好 -256.0，且 45 张里没有任何一张有角点低于它**；
  最高 1536.0。而 -256 = layer 0 的世界基准 `(0-2)*128` → 硬地板，不是巧合。
- 我们的图：群岛 -500 / 丘陵 -374 / 山脉 -324 / **对战图 cliffs -333**（老代码也越界，
  所以这不是 hills 模式独有，是一直存在的 bug，用户第一次真正去 WE 里改才发现）。

**两个越界来源**：
1. 单层模式：layer 常数 2，落差全在 gh 里 → 深水区直接跌到 -500。
2. 悬崖模式：水角点 layer 降到 `water_layer-deep_layers`，而水下起伏
   `relief_w = fine*(amp/sigma)` **只裁了向上余量（`np.minimum`）、没有下限**，
   再叠上降层就跌穿。

**修法（gen_height.py，默认开 `--world-clamp 1`）**：
1. 单层模式**自动抬高整图层号** `L = 2+ceil((-256-H_min)/128)`（垂直平移，相对水面
   关系不变 → **观感无损**，打印「抬高整图到第 N 层」）。512 振幅 → 抬到第 3/4 层。
2. 全模式保底钳制 world 到 [-256, 1536]。
   ⚠️ **踩坑：钳制一开始放在「深水降层」之前，用的是旧 layer，深水角点全漏过去了**
   （日志显示 cliffs 仍是 -333）。必须放在降层之后。

**验证**：
- 5 尺寸 × 5 种子 × 2 模式 = 50 张，world 全部落在 [-256, 1536] ✔
- 回归：`--cliffs 1 --water-relief 0`（不触发钳制）时，4 组种子/尺寸与旧版**逐字节一致**
  → 证明改动只落在钳制这一处，其余路径没动。
- ⚠️ 因此 **cliffs 模式默认参数下会触发钳制（1317 个深水角点被压平到 -256），
  与改动前的图不再逐字节相同** —— 这是修 bug 的代价，深水底部本来就看不见。

**未修但判断无害**：`d_gh`（相邻 gh 差）237 vs 官方 162.5；但 `d_world`（真实坡度）
344 < 官方 408.8。官方把落差放 layer、我们放 gh，只看 d_world 才公平。

### 结论先说

- 换句话说：**我们的水整片都落在「官方从没出现过」的深度区间里。**

### 结构差异（`field_diff.py`，逐字段比官方图）
- 我们：水区与陆地 **同层（layer 全 2）**，深度全靠 groundHeight；groundTexture 全 0、cliffTexture 全 1。
- 官方（LostTemple / SwampOfSorrows）：**水区 layer 恒比周围陆地低 1~2 个整层**（水 0/1，陆 2~8），
  gh 基本不动 → 水底 = 下整层台阶。**37/38 张官方图都是「水在更低的一层」。**
- 猜测：WE/引擎可能按 **layer 差** 判定「是不是水」，同层 gh 下沉被当成「洼地/干地」→ 渲染成陆地。

### 官方 wpm 实测（`wpm_depth_probe.py` / `wpm_depth_threshold.py`）
- 官方图 wpm 取值只有 6 种：**64 / 72 / 8 / 10 / 202 / 206**。
- 交叉表（按逐角点水深分桶）：
  - **64 (0x40)** 陆地；**8 (0x08)** ← 1 档深(128WE)的水；**10 (0x0A)** ← 2 档深(256WE)的水。
  - **72 (0x48) = 0x40|0x08** 只在「浅于 ~80 WE」的水/岸出现（深度 0 时占 24%）→ 疑似「可走的浅水」。
  - 202(0xCA)/206(0xCE) = 边界/不可走，**都带 0x02 位** → 0x02 疑似「不可通行」位；
    而 8 不带 0x02、10 带 → **若成立：1 档浅水可走、2 档深水不可走**（和用户「浅水能走」的直觉一致）。
- 0x40「可走」标志随深度衰减：≤80 WE 时 ~98-100%，104 WE 掉到 40%，128 WE 只剩 33%。

## 第四轮（傍晚）：修「悬崖间的斜坡凹到地心」（用户反馈）
用户原话：「你这个斜率太大了，都凹陷到地心了，明明加个一般斜坡就行」

### 根因
斜坡角点高度走 `世界高度 = fine/4 + 128×(layer-2)`。老代码为「坡面不带起伏」把坡带 `fine`
**清零** → 等于按到**层基准线**（layer 基准），离台地地面整整差一个 `Hgap`。
实测 seed=777：坡面 **1~256 WE** vs 紧邻台地 **550~620 WE** → 400~500 WE 深沟。

### 修法（要点：坡带高度 = 「同层号 + 朝台地那一侧」的地面高度）
新增 `fill_band_fine(fine, layer, band, radius=8, win=4)`：
① **局部 PCA**（取该角点 4 格邻域内的坡带角点）求切线，法线 = 切线转 90°；
② 用「层号高的角点在法线正侧」定向，低层线取 −法线、高层线取 +法线；
③ 方向**吸附到 8 邻域里的一个**，沿**严格直线**找第一个同层号非坡带角点，取它的高度；
④ 找不到 → 任意方向同层号平均 → 盒式模糊兜底。结果坡带线 = 两侧台地地面的**逐角点复制**。

3. 小林丛（质感）：株数**对数正态**、随机取向**椭圆+噪声抖动**（非规则圆斑），禁区 `d_an ≤ 2rad+gap`，

4. 散株：按 `(1-field)` 加权；`grow_along_edge` 林缘补生仅兜底。

## 第 N 轮：陆水衔接「坡度小一些」（用户原话：感觉陆地和水衔接的地方没有那么自然）

### 结论：真凶在**水下**，不在陆上
陆侧剖面其实和官方几乎一样（离水 1~5 格的平均高度 官方 31/68/102/121/132，我们 41/70/93/110/125）。
差别全在水里 —— 官方是**逐格加深的浅滩**，我们是**一步到 128 的平底**：
    离岸 k=1/2/3 格的水深中位数：官方 68 / 114 / 128　我们 128 / 128 / 128
    40 张有水的官方图里「水深 <128 的水角点」占比中位数 **41%**（Riverrun 57%、BloodvenomFalls 72%），我们 **0%**。
→ 岸线因此是一道 169 WE 的硬台阶（陆 +41 → 水 −128），WE 里看着就是「浴缸边」。

### 实现（gen_height.py）
新增 `--shore-width`（默认 3）/ `--shore-shallow`（默认 0 = shelf_depth 的 53%，128→68）：
离岸 k 格水底的目标深度用**二次曲线** `shelf - (shelf - shore_s)·(1-t)²`，t=(k-1)/(w-1)，
代进 68/128、w=3 时 k=2 = 113，与官方 114 吻合。只动水角点（抬浅），陆地一个数不碰
→ 不破坏「层差 = 落差/128」不变量（水角点永远不是台地）。

### 🔴 两个坑
1. **变量名 `target` 撞车**：`main()` 里 `target` 是输出地图路径，我把浅滩剖面也取名 `target`
   → `subprocess.run([exe,"add",target,...])` 拿到 ndarray 崩在 `list2cmdline`。**别再叫 target**。
2. **量化后还有一道「水角点强制深度兜底」**（`fine ≤ -4×shelf_depth`）会把刚抬上去的浅滩抹平
   （A/B 两图只有 1 个角点不同，就是这个）。修法：把浅滩剖面存成唯一来源 `shore_prof` 数组，
   那道兜底改读 `np.maximum(hstep, shore_prof*4)`。**同一口径只能有一份实现**（老规矩）。

### 口径澄清：waterHeight 不是逐角点水面
它是**全图恒定的水面平面绝对 raw 高度**（官方图 99.7% 角点是同一个值：Riverrun 9728、
LostTemple 8192；我们自己 gen_height L2415 也是写常量 `plane_raw`）。
所以 `surf=(wh&0x3FFF-8192)/4`、`h=world-surf` 是对的 —— 上一段一度据此判废，是误判。
⚠️ 但 flag 0x40 **不等于** h<0：官方图里有大量「打了水标记却在平面之上」的角点
（TheCrucible 98%、BloodvenomFalls 74%），所以 flag 只能当「水体范围」、深度要另算。
⚠️ 引擎「水深 <128 渲不渲水」仍未 100% 定论（探针说 ≥128 才画，但官方 41% 的水角点更浅）。
两种情形下岸线缓坡都收敛到官方观感，所以按官方分布做是安全的；产物可直接开 WE 肉眼定夺。
