# 项目长期记忆：automap（WC3 随机地图生成器）

## 目标
类似红色警戒 2 的 WC3 随机地图生成器：运行 → 随机地形 → 保存 .w3x → WE 打开手动改。
核心是**操作 MPQ 里的 war3map 二进制文件**，不是游戏运行时脚本。

## 开发顺序（用户明确要求的分层路线）
1. **地形 + 地图装饰物**（war3map.w3e / war3map.doo）——先做到用户满意才进下一步
2. **中立建筑**（金矿、商店等）
3. **野怪与其他中立单位**（war3mapUnits.doo）——最后做
每层的验收由用户在 World Editor 里目测确认，确认后才进入下一层。

## 项目边界
- `automap/` = 随机地图生成器（本项目），零外部依赖，自带 bin/MPQEditor.exe
- `mapgen/` = 另一个项目，做「图片 → 地图贴图纹理」，两者互不引用

## 生成方式的本质（重要）
**当前 = 「复制模板地图 + 只覆盖 2 个文件」**。默认模板已从 LostTemple 换成
`template/*.w3m`（用户自建空模板，见下节）。LostTemple 模板共 16 个 MPQ 文件，
实测只有 `war3map.w3e`（地形）和 `war3map.doo`（装饰物/树）被替换，其余 14 个
与模板**逐字节相同**（md5 一致）：
- `war3mapUnits.doo` —— 单位：出生点 sloc×4（owner 0/1/2/3）、金矿 ngol×12（owner 15，
  金量 12500）、商店 ngad×2 / ngme×2 / nfoh×1、**100 个 owner=12 的野怪**。
  这些仍留在 LostTemple 的原坐标上，与我们的新地形对不上
  （实测：25/121 落进水里、6 个在悬崖上、z 与地形高度平均差 243 WE 单位；
  模板自身基准 21.4）。
- `war3map.wpm` 寻路图 / `war3map.shd` 阴影图 / `war3mapMap.blp` 小地图图 /
  `war3map.mmp` 小地图图标 / `war3map.j` 脚本 / `war3map.w3i` 地图信息 —— 全是模板的。
**WE 保存时会重算 wpm/shd/blp，但不会重算 units/mmp/w3i**，所以这几项必须我们自己写。

## 空模板 `template/`（用户手工用 WE 新建，2026-09-15 起为主力模板）
| 文件 | 尺寸 | w3i | units.doo | 0x4000 角点 |
|---|---|---|---|---|
| 64-64 / 96-96 / 128-128 / 160-160 / 192-192 `.w3m` | 同名 | v18 | v7.9 n=1 | 1392 / 2160 / 2928 / 3696 / 4464 |
| 224-224 / 256-256 `.w3x` | 同名 | **v25** | **v8.11 n=1** | 5232 / 6000 |

- 全部**完全平坦**（groundHeight 恒 8192、layerHeight 恒 2）、`war3map.doo` **0 装饰物**、
  `flags` 的 0x80 **全图 0**。纹理集统一 `L` Lordaeron Summer。
- 唯一残留内容 = **1 条 sloc**（owner=0）——WE 新建地图必塞，删不干净，由生成器重写。
- ⚠️ **224/256 是 1.31+ 编辑器产物**（w3i v25、doo/units v8.11），记录长度与 v7.9 不同
  （同一条 sloc：v7.9 文件 111 字节 / v8.11 是 127 字节）。**1.27a 大概率读不了，别用**，
  除非先在 1.27a 的 WE 里另存一遍归一化。
- 生成格式体 v7.9 / 1.27a 原生，因此主力模板只用 5 张 `.w3m`。
- 体检工具：`tools/inspect_template.py`（支持传目录，逐张出报告）。

## 已确立的技术事实
- w3e v11：7 字节/角点；WE 高度 = (groundHeight-8192+(layer-2)*512)/4；层零位 2，每层 512，layer=15 崩溃
- flags 高 4 位：0x10 ramp / 0x20 blight / 0x40 water / **0x80 边界外**（水不是 0x80！）
- **0x80（flags）与 0x4000（waterHeight）是同一个「地图边界外」概念的两份标记**。
  实测 LostTemple：带这两位的瓦片寻路可走率 **0%**；它俩覆盖了 LostTemple 40% 的角点。
  模板里这两个位必须整图清零，否则 WE 会把生成的地形当成地图外。默认只在最外一圈保留。
  - **语义细分（2026-09-15 实测）**：WE 自建的空模板里，0x4000 覆盖的角点数
    = 全图角点数 − 游玩区角点数 − 24（7 张模板恒定差 24）→ WE 用它标「游玩区边框之外的留白」；
    官方对战图则拿它盖 40% 当真地图外框。两种都是「不可走」，但用途不同。
  - `--boundary`：`ring`（默认，只留最外一圈，整张图可玩）/ `none`（全清）/
    `keep`（沿用模板边框，并把 0x80 同步到 0x4000 的同一批角点，两个位必须一致）。
- 带 ramp(0x10) 的悬崖瓦片寻路可走率 79% ✔（ramp 语义确认）
- war3map.doo："W3do" v7.9，定长 42 字节/条，尾部 8 字节。
  记录布局 id(4) variation(4) x,y,z(12) rotation(4) scale*3(12) flags(1) life(1) itemTable(4)
  z = 该格四角 WE 高度均值（实测 7215 棵树误差 0.000）
- war3mapUnits.doo："W3do" v7.9，121 条记录 / 11895 字节。**变长记录 91~139 字节**，
  长度公式尚未完全定死（部分记录尾部比模型多 4 字节），所以解析用「扫记录开头 +
  固定前缀偏移」而不是顺序解析。前缀偏移（p = 记录起点）：
  p+0 id(4) / p+4 variation(4) / p+8 x,y,z(12) / p+20 angle(4) / p+24 scale*3(12) /
  p+36 flags(1) / p+37 owner(4) / p+41 未知(2) / p+43 hp(4,-1=默认) / p+47 mana(4) /
  p+51 掉落集合数(4) → p+55 起 [条数(4) + 条数×(itemId4, chance4)] / 紧随其后 gold(4) /
  targetAcq(4) / heroLevel(4) / n_inv(4) / n_ab(4) / 尾部：随机标记(4) 颜色(4) waygate(4) creation(4)
  owner 含义：**12 = 中立敌对（野怪）**、15 = 中立被动（金矿/商店）、0..3 = 玩家槽位（出生点）。
  出生点 id = `sloc`，金矿 id = `ngol`。
- **units 文件可以从零手写，不需要逆向变长格式**（2026-09-15 验证通过）：
  `build(count, recs, tail) = struct.pack("<4sIII", b"W3do", 7, 9, count) + b"".join(recs) + tail`
  空文件 = 24 字节（count=0 头 16 + 尾 8，尾部沿用模板的 `ffffffff6d000000`）。
  一条 91 字节的 sloc 记录可直接从模板裁剪后 `pack_into` 改 owner(p+37) 与 x,y,z(p+8)。
  验证脚本：`tools/_tmp/utest/test_write_units.py`（空/1 条/4 条都回读一致）。
  → 层 2/3 直接整文件重写 units.doo 即可，把模板残留单位一次清干净。
- 找记录开头的过滤条件（实测有效）：id 4 字节合法且首字母 ∈ nouehrsNOUEHRS、
  variation ≤ 64、flags < 0x10、owner ∈ [-1,16]、hp ∈ {-1} ∪ [0,100000]、
  x/y 在地图范围内、z ∈ (-2000, 2000)
- war3map.wpm：magic **"MP3W"**（不是 MPWN），v1，4 倍分辨率（160x160 图 → 640x640）。
  取值：64(0x40)=可走地面；206(0xCE)/202(0xCA)=边界外无寻路；8/10=水。
  **生成器目前不改 wpm** → 生成图的寻路仍是模板的，WE 保存时会按地形重算。
- 世界坐标：瓦片中心 x=(i+0.5)*128-W*64，y=(j+0.5)*128-H*64（j 自下而上）
- w3e 文件行序自下而上：图像行 cy=0（顶部）写到文件行 rows-1

## 随机地形算法要点（踩过的坑）
- **八度数（octaves）别超过 2** —— 高八度噪声 + 量化 = 地形被切成几十块走不通的小台地
- **层位偏置 level-bias 是治碎片化的关键**：秩均匀分位会让每层各占 1/levels 土地 → 马赛克。
  对 land_q 取幂（默认 2.0）还原「大片平地 + 少量高地」的重尾分布，台地从 34 块降到 ~10 块
- 3x3 众数滤波（smooth=2）抹平单角点毛刺；两次即收敛
- 斜坡连通用「多源 Dijkstra 求台地邻接图 → Kruskal 生成树 → 沿路径铺 0x10」，
  不用「两侧必须紧挨平地」的脆弱判据（那种判据在过渡带 >1 格宽时全部落空）
- 连通性自检的正确口径：**逐个陆地岛检查岛内可走瓦片是否同属一个连通块**，
  不能拿「陆地连通块数」和「可走连通块数」直接比（前者含崖壁瓦片，口径不同永远不等）
- ⚠️ **已知待办：连通性失败率偏高**（10 seeds/尺寸，`gen_height` 独跑实测）：
  64-64 **6/10**、96-96 4/10、128-128 3/10、160-160 1/10、192-192 1/10。
  失败 = 同一座陆地岛内部被崖壁切成两个走不通的区域（某块地图到不了）。
  与高度/应用高度改动无关（台地数稳定在 5~8 块，没有碎片化回归），
  出在 `carve_ramps` 的边角情况上。小尺寸模板尤其明显。

## 树木分布（2026-09-15 重做，`place_clumps`）
**不要用「噪声场取分位阈值」撒树**：等值线是连续闭合曲线，取分位得到的必然是一个大
连通块，覆盖率一高就糊成整片实心林（实测 3841 棵 = 8 片、最大 3051 格）。调 freq/octaves
只能改块的大小，改不掉「实心」。
现在用**树丛播种**：丛心按「森林场 × 随机抖动」打分 + **最小间距 `--clump-gap × 丛半径`**
贪心接受；每丛株数/半径都做抖动；丛内按「距离+抖动」排序取够株数；株数不够时**沿林缘
生长**（维护 frontier，只从有空位的林缘格抽），不许用「随机抽空格」兜底 —— 那会撒出一堆
孤立单株，观感更差。旋钮：`--density / --clump-size / --clump-radius / --clump-gap /
--clump-bias / --scatter`。判定指标用 `blob_stats()`（连片块数 / 最大块 / 平均块 / 孤立率）。
同规模下：最大块 3051 → ~200 格。
⚠️ `np.mgrid[y0:y1,x0:x1]` 是 (nj,ni)，`elig[x0:x1,y0:y1]` 是 (ni,nj)；**半径是常量时窗口
永远是正方形所以不会报错**，一改成随机半径就 broadcast 炸。

## 高度层范围（`--layer-min` / `--layer-max`）
每层 = 128 WE 高度，直接决定「悬崖能爬多高」。水面固定 `layer_min - 1`（永远比最低陆地
低一层）。`--layers` 保留兼容 = `layer_max = layer_min + layers - 1`。合法 range 1..14。

## 🔴 挡路的只有「层差」，层内坡度不挡路（2026-09-15 实测，推翻了旧假设）

两个测量（`tools/_tmp/check_gh_deviation.py`、`check_slope_walkable.py`，315 张官方图）：

1. **层内 groundHeight 没有 ±512 的限制**。官方图 **43% 的角点**层内偏移超过一整层，
   最大 **6144 原始单位 = 1536 WE = 12 层落差**；`Human05Interlude.w3m`、`OrcX03a.w3x`
   这类图**全图只有 1 个 layer 值**却有上千 WE 的连续落差 = 一个悬崖都没有。
2. **层内坡度不产生不可通行**（拿官方 wpm 当标准答案）：只看「四角同层」的瓦片，
   瓦片内高差从 8 WE 涨到 190 WE，可走率只是从 87.8% 缓慢降到 70.4%，**没有塌到 0 的阈值**
   （剩下的不可走是树/装饰物占位）。对照：层差 = 1 且无 ramp 的瓦片可走率 **0%**。

> 原则：**layer 差异 = 悬崖 = 挡路；层内 ├──起伏 = 不挡路，只是观感。**
> 以前把层内振幅限制在 ±~384 原始单位是**毫无必要的保守**，官方能到 ±6144。

由此得到一种新的出图方式：
- `plateau` 模式（现有）：层堆叠 → 台地 + 悬崖 + 斜坡，像官方对战图
- `hills` 模式（待做）：**全图单层** + 大振幅连续起伏 + 用 `waterHeight` 水面切出陆地
  → 连绵丘陵，**零悬崖**，近战友好；而且 water 也不必靠层表示（同层 + gh 沉到水面下
  就能做出平滑入水的沙滩）
- `--layer-min == --layer-max` 现在是合法的（`gen_height.py` 已放行），= 单层模式

## 应用高度：隆起 / 凹陷 / 凹凸不平 / 台阶（2026-09-15 新增）
对应 WE 地形面板「应用高度」那一栏。全部幅度参数的单位 = **WE 高度单位（高度条上 1 格），
一整层 = 128**；`unit_noise()` 把噪声场归一到零均值+单位标准差，**所以参数值 ≈ 实测 σ**。

| 参数 | 默认 | 含义 |
|---|---|---|
| `--raise` / `--lower` | 75 / 75 | 低频场的正/负半边幅度，拆开才能"只鼓不凹" |
| `--rough` | 12 | 细颗粒幅度（WE 噪波笔刷本身很轻，别当成大噪声） |
| `--blob` | 28 | 隆起/凹陷的团块尺寸（**格**，与地图尺寸无关） |
| `--grain` | 2.5 | 凹凸不平的颗粒尺寸（格） |
| `--ledge` | 0 | >0 时把宏观起伏量化成「平坦面+陡坎」，≈ WE 的高原/阶梯笔刷 |
| `--height-step` | 4 | 高度量化步长（原始单位），4 = 1 WE 单位 = WE 笔刷粒度 |

**官方对战图基准**（157 张，`tools/_tmp/analyze_height.py`；口径 = 台地内残差，
5x5 均值算低频、其余算高频，单位 WE 高度）：
合计 σ **86.6** / 低频 σ **69.7** / 高频 σ **31.9** / 邻差中位 **5.5** / 邻差 p99 **89**。
- 官方**低频偏高、高频也偏高**，但**36%~64% 的相邻角点完全等高**，残差取值多为 4 的倍数
  → 官方地形 = 「大片平坦面 + 1 WE 单位量化的陡坎」，不是处处连续的坡（GnollWood 邻差中位=0）。
- ⚠️ **高频 σ=32 拿"颗粒"换不来**：调大 `--rough` 只会变成 45° 砂纸。官方那 32 来自
  **台阶边缘**（5x5 窗口跨坎的方差）。要复现必须开 `--ledge 20~30`（默认 0，观感更自然）。
- 改完实测：低频 70.8 ✔、邻差中位 5.0 ✔、合计 75.7，高频 15.5（仍只有官方一半，见上）。
- 用户原来那张"塑料板"图：`fine` 最小波长 7.6 格 → 低频 σ 只有 7.9、高频 1.5。

**`value_noise` 的三个伪影修复（都很容易再犯，别退回去）**：
1. 插值权重必须用 **smoothstep（3w²-2w³）**，线性插值在格线上留折痕，多八度叠起来
   就是一片 45° 砂纸斜纹。
2. 格点**相位要随机偏移** + `np.mod` 环绕。格点数与角点数整除时（129 角点配 65 格点）
   噪声节点正好落在每个像素上，渲染出规则点阵/棋盘。
3. `fbm()` 里八度细过「一个角点一格」就 `break`，再细的内容在角点网格上只是混叠假图案。
- 预览图叠了 `hillshade()`（山体阴影，exag=10 只影响预览）：不叠的话纯色块上根本
  看不出隆起/凹陷/颗粒感。日志同时回显 `实测层内起伏: 合计/低频/高频 σ ← 官方 87/70/32`。

## 水面 / 浅水深水 / 水下起伏 / 平整区域（2026-09-15 新增）

### 水面机制（实测 157 张官方图，`tools/_tmp/analyze_water.py`）
- **水面世界高度 = 最低陆地层的底线** = `GROUND_ZERO + (layer_min - 2) * 512`
  = 浅水层（`water_layer = layer_min - 1`）的**顶面**。默认 layer_min=2 → 8192。
- w3e 的 `waterHeight` 字段：**低 14 位就是水面原始高度，0x4000 是边界位**。
  校验/分析时直接读这个字段，不要靠 layer_min 推算（我在校验脚本里漏传过一次参数，
  直接把 2822 个水角点误报成「水面以上」）。
- **官方地图的水深全是「整层」的倍数**：最常见 1 层（=128 WE 高度），其次 2 层（256），
  少数 4 层。所以深水不是渐变，是**下整整一层台阶**，和台地一样。
- ⚠️ **官方地图普遍存在「陆地低于水面」的角点**（有的图高达 7 成，最深 -128 WE）。
  **「陆地必须高于水面」不是不变量，别拿它当 bug 修。**

### 参数
| 参数 | 默认 | 含义 |
|---|---|---|
| `--flat` | 0.15 | 平整（完全没有隆起/凹陷）区域占陆地的比例 |
| `--flat-size` | 20 | 平整区域的团块尺寸（格） |
| `--shelf` | 3 | 浅水岸带宽度（格）：离岸 ≤ 此值的水格是浅水，之外是深水 |
| `--deep` | 1 | 深水比浅水再深几层（0 = 关闭深水，全图只有一种水深） |
| `--water-relief` | 0.5 | 水下起伏 = 陆地起伏 × 该比例 |

### 实现要点
- 平整区域：低频场取**最低**的 `flat` 分位（`percentile(ff, flat*100)`，写反成 `1-flat`
  会让 85% 全变平），核心区起伏乘 0，边缘用 25% 跨度过渡；场再减
  `0.35*(1-code/nlev)` 偏袒低层 —— 官方平整区都在平原上，不会长在高台地。
- 浅水/深水：`shore_distance()` 多源 BFS 求「水格到最近陆地的格数」，
  `edge = clip(shelf*(1+0.7*抖动), 0.5, None)` —— **岸带宽度必须抖动**，否则像描边。
- 水下起伏：按陆地 σ 等比缩放后 `minimum(fine, cap)`，**向上余量 = `LAYER_STEP - LAYER_STEP/4`
  = 384 原始单位**（水面到浅水层底正好 512，留 1/4 层安全边），保证永不冒出水面。
- 深水落层：`layer = water_layer - deep_layers`（更暗的水色就是这么来的）。

### 两个真 bug（教训）
1. **`--layer-min` 曾完全不生效**：`layer` 是用常量 `LAYER_ZERO` 拼的，不是 `layer_min`
   → 调它只改层数、不改地形高度。**在主赋值和 despeckle 块两处都要用 `layer_min`。**
2. **`waterHeight` 曾写死 8192**：`--layer-min` 一抬高（如 6），水面就落到地形下面，
   整张图一滴水都看不见。必须 `plane_raw = GROUND_ZERO + (layer_min - LAYER_ZERO) * LAYER_STEP`。

### 工具 `tools/inspect_water.py`（常驻）
水面从 waterHeight 字段低 14 位读（自动跟随 layer_min），死条件 = 带 0x40 水标记的角点
世界高度必须 < 水面。输出水深分位 / 按 layer 分档 / 同层水深 σ / 离岸距离分布，
并明确标注「陆地低于水面」是官方正常现象。绝不用常量 8192 当水面。

### 预览

## 临时目录与删除（重要，通用）
`shutil.rmtree` / `os.remove` 在沙箱里会被删除保护**直接拦截**，症状是「地图已经写好了，
但进程返回退出码 1」，看起来像生成失败。
→ 两个工具统一用 `make_tmp(name)` / `drop_tmp(tmp)`：**父目录尽力清空 + 本次唯一子目录
`r<pid>_<ms>`**；唯一目录保证不会有上次残留文件被当成新数据（MPQ 提取失败时最容易踩），
清理包在 `except BaseException` 里尽力而为。`tools/gen_height.py`、`tools/add_doodads.py`
里已无 rmtree。

## 编码：管道里一律 UTF-8（踩过大坑，2026-09-15）
症状：用户跑 GUI 时报 `UnicodeDecodeError: 'gbk' codec can't decode byte 0xa2`，
紧接着 `AttributeError: 'NoneType' object has no attribute 'strip'`。
**真因两层**：
1. `✔ ✘` **不在 GBK 字符集里** → 子进程按 cp936 输出时直接 `UnicodeEncodeError`（在 gen_height
   的斜坡自检那行崩的）。
2. 解码失败发生在 `subprocess` 的**读取线程**里 → `r.stdout` 变成 `None` → 调用方
   `r.stdout.strip()` 抛 AttributeError，报错完全指不到真因。
3. 为什么我本地复现不出来：沙箱环境默认 `PYTHONUTF8=1`（UTF-8 模式），父进程顺带就按
   UTF-8 解码了。**排查这类问题必须 `env -u PYTHONUTF8 -u PYTHONIOENCODING` 再跑一遍。**
**约定（所有工具统一）**：
- 每个脚本开头调 `force_utf8_stdout()`：`isatty()` 为真（人在控制台看）保留控制台编码 +
  `errors="replace"`；为假（进管道/被重定向）强制 `encoding="utf-8"`。
- `subprocess.run(..., text=True)` **必须显式写 `encoding="utf-8", errors="replace"`**，
  绝不依赖默认的区域设置。random_map.py 里统一走 `run_child()`，并用
  `CHILD_ENV = dict(os.environ, PYTHONIOENCODING="utf-8", PYTHONUTF8="1")` 固定子进程环境。
- 读 `r.stdout` / `r.stderr` 前一律 `or ""`。
