# 中立建筑随机生成方案（层 2）

> 目标：地形 OK 之后，在图上按「玩家选的种类 + 数量」摆放中立建筑（金矿 / 地精商店 /
> 地精实验室 / 雇佣兵营地 / 生命之泉 / 市场 / 酒馆），并整文件重写 `war3mapUnits.doo`。

## 一、war3mapUnits.doo 记录格式（实测，解析到文件尾零误差）

验证口径：**顺序解析到最后一条记录正好落到文件尾**，且**逐字段回写后与原字节完全相同**。
43 张 1.27a 原生 `.w3m` + 113 张 TFT 官方 `.w3x` **全部通过**（`tools/w3units.py` self-test）。

```
文件头 16 字节: "W3do" + u32 version + u32 subversion + u32 n_units

每条记录（v7.9 / v8.11 前缀相同，都是 51 字节）:
  p+0   id(4)            p+36 flags(u8)        ← 实测 v8 也是 1 字节，不是 u32
  p+4   variation(i32)   p+37 owner(i32)       ← 12=中立敌对 15=中立被动 0..11=玩家槽
  p+8   x,y,z(f32×3)     p+41 unknown(u16)
  p+20  angle(f32)       p+43 hp(i32)  -1=用默认
  p+24  scaleXYZ(3×f32)  p+47 mana(i32)
  p+51  n_sets(i32) → 每个集合: n_items(i32) + n_items×(itemId4, chance i32)
  ── 掉落之后 ──
    gold(i32)  targetAcquisition(f32)  heroLevel(i32)
    [v8.11 且 subversion≥11] 英雄三围 str/agi/int(3×i32)
    n_inv(i32) + n_inv×(slot i32, itemId4)
    n_ab(i32)  + n_ab×(abilityId4, autocast i32, level i32)
    randomFlag(i32) —— 后面的条件数据长度随取值变：
        -1 → 0 个 i32（出生点 sloc 属于这种）
         0 → 1 个 i32（值 0/1，绝大多数普通单位 / 建筑属于这种）
         1 → 2 个 i32（如 (4)TranquilPaths 的 uDNR）
         2 → 单个物品集: n_items(i32) + n_items×(itemId4, chance i32)
    尾部固定三字段: customColor(i32)  waygate(i32)  creationNumber(i32)
```

⚠️ v8.11 与 v7.9 的差别只有「`mana` 后多 `itemTablePointer(i32)`、`heroLevel` 后多英雄三围」，
**flags 仍是 1 字节**。这点和网上流传的「v8 flags 是 u32」不一致，以实测为准
（(2)Circumvention.w3x 第一条 ngol：`52=0x02` 是 flags、`53..56=15` 是 owner）。

⚠️ `randomFlag` 的分支是踩过坑的地方：早期按「掉落表」解析 `rnd==2`，导致 8 张图解析断裂/越界。
真正的规则是 `rnd==2` 后面跟**单个物品集**（不是集合列表）。

### 朝向：一律 270°，不随机

实测 43 张 1.27a 图 + 112 张 TFT 官方图（脚本 `tools/_tmp/bld_angle.py`）：

| id | 样本数 | 朝向 |
|---|---|---|
| ngol 金矿 | 1933 | **270° × 1933（100%）** |
| ngme 地精商店 | 325 | 270° × 325（100%） |
| ntav 酒馆 | 207 | 270° × 207（100%） |
| ngad 地精实验室 | 198 | 270° × 198（100%） |
| nfoh 生命之泉 | 84 | 270° × 84（100%） |
| nmer 雇佣兵营地 | 67 | 270° × 67（100%） |
| nmrk 市场 | 34 | 270° × 34（100%） |
| 雇佣兵营地变体 nmr0~nmr9/nmrc/nmrd/nmre | 164 | 270° × 164（100%） |

**2900+ 座中立建筑，一个例外都没有。** 270° 是 WE 里放下建筑时的默认朝向（模型面朝「下方」），
官方从不改它。所以 `add_buildings.py` 写死 `UNIT_ANGLE = 4.712389`，
只有显式传 `--angle-jitter <度>` 才会偏离（默认 0，不进 GUI）。

对照：**野怪（owner=12）是真随机** —— 644 个 nftr 就有 546 种不同朝向，nftb 609 个有 485 种，
接近连续均匀分布。所以层 3 做野怪时朝向**要随机**，别照建筑这套来。

字段众数（用来生成「与官方逐字段一致」的记录，已写进 `w3units.Unit.DEFAULTS`）：
`flags=2 owner=15 hp=-1 mana=-1 tacq=-1.0 heroLevel=1 randomFlag=0(+1) customColor=-1 waygate=-1 scale=1`，
金矿 `gold` 取 12500（1.27a 对战图的众数；另有 12000/16000/13000）。

## 三、摆放算法

1. **可放置判据**（`flat_ok`）：以 tile 为中心、半径 r 的方窗内所有 w3e 角点满足
   非水 + 非「地图边界外」（`flags&0x80` 或 `waterHeight&0x4000`）+ 层差 ≤ 容差。
   用 `sliding_window_view` 做向量化，192×192 地图瞬间出结果。
2. **占位避让**：读 `war3map.doo` 取装饰物坐标 → 树格及其 4 邻域不可放；
   已放建筑按间距生成圆形禁区；出生点周围 7×7 也留空。
3. **最远点采样**（`place_spots`）：每放一座就把「到最近已放建筑的距离」更新一遍，
   下一座从距离最大的前 5% 里随机挑 —— 铺得开又不会每次排出同一个图案。
4. **朝向**写死 270°（`UNIT_ANGLE = 4.712389`），官方 2900+ 座建筑 100% 都是它，不随机。
5. **出生点**：模板自带的 `sloc` 默认保留；若新地形下落水/落崖，就重新找一块合法平地并修正 z。
5. `creationNumber` 按顺序重排（官方图里每条记录都有唯一编号）。

⚠️ 掩码一律形状 `(W, H)`、索引 `[i, j]`（与 `add_doodads` 的 `picked` 同口径）。
ravel 后是 C 序 → 索引 = `i*H + j`，解回来必须 `divmod(pick, H)`；
写成 `(pick % W, pick // W)` 会把 i/j 转置 —— 方块图看着对、实际位置全错（踩过：5/20 座落进水里）。

## 四、参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--buildings 0` | 1 | 总开关，0 = 完全不放（`random_map.py` 层） |
| `--ngol/--ngme/--ngad/--nmer/--nfoh/--nmrk/--ntav N` | 见上表 | 每种建筑的数量，0 = 该类不放；未列出的 id 可用 `--nb-<id> N` |
| `--min-dist` | 8 | 建筑之间的最小格距 |
| `--edge` | 6 | 距地图边缘最少留几格 |
| `--flat-tol` | 1 | 占地范围内允许的层差（0 = 必须完全同层） |
| `--gold` | 12500 | 金矿储金量 |
| `--angle-jitter` | 0 | 朝向抖动（度）。0 = 严格照官方 270°；给个值才会随机偏离 |
| `--avoid-trees` | 1 | 避开装饰物（树） |
| `--keep-sloc` / `--keep-units` | 1 / 0 | 保留模板出生点 / 保留模板全部单位 |
| `--preview` | — | 输出 `*_buildings.png` 位置预览 |

## 五、验证方式

- `python tools/w3units.py <图>...` —— 解析到文件尾 + 逐字段回写零误差（43+113 张官方图全通过）
- `python tools/inspect_units.py <图> --dump 25` —— 建筑是否落水/落崖/出界、z 与地形高度对账
- GUI 上跑一遍（参数组合验证一律走 GUI，前端默认值与透传逻辑和命令行不等价）
- 最终由用户在 WE 里目测
