# 野怪（层 3）方案 —— add_creeps.py

> 数据口径：45 张官方 1.27a / TFT 对战图，1269 个野怪点（owner=12 单链接聚类，阈值 700）。
> 统计脚本 `tools/_tmp/creep_stats.py`，组合模板导出在 `tools/camp_templates.py`。

## 两种野怪点（官方实测）

| 类型 | 官方占比 | 选址 | 大小 |
|---|---|---|---|
| 守建筑 | 金矿 63% / 商店 65% / 实验室 59% 有守卫 | 点心离建筑 2~5 格（金矿 p50=3.2 格、商店 2.4 格） | p50=4 只 |
| 林中（树林角落） | 其余 37%（464/1269） | 离任何建筑 >9 格，贴树林（我们要求 5×5 窗口 ≥3 格有树） | p50=3 只 |

窝大小 p10/p50/p90 = 3/4/5 只；半径 p50 ≈ 215 WE ≈ 1.7 格。

## 组成
从官方图实测的 183 个组合模板（出现 ≥3 次）按频次加权抽样 —— id 与数量搭配全是官方原样
（nftr/ngst/nfsp/nwlt/uDNR… 均在官方图出现过）。

## 朝向
🔴 **野怪 angle 是真随机**（官方 644 只 nftr 有 546 种朝向）——与 owner=15 建筑
100% 写死 270° 相反，别混用。

## 掉落（默认开）
- 官方 1240/1269 个窝带掉落；`chance` 全部 100；每份掉落 = 1 个 set × 1 条随机物品表。
- 份数随窝规模：n=2→0.9、3→1.3、4→1.7、5→1.8、8→3+（`EXPECT_DROPS`）。
- (类别,等级) 直接查官方联合分布表（`DROP_JOINT`，key=min(n,7)）—— 类别和等级**不独立**：
  Yk（永久）只出 1~2 级、Yl（神器）只出 7~8 级；窝越大等级整体上移。
- **掉落按野怪等级分配**（2026-09-17 用户反馈后加）：
  - 野怪等级 = 游戏 `Units/UnitBalance.slk` 的 `level` 字段（`tools/creep_levels.py`，
    由 `tools/_tmp/creep_levels.py` 用 mpyq 从 war3.mpq / War3x.mpq / War3Patch.mpq 导出，
    模板 113 种 id 覆盖 112 种，uDNR 是随机占位符无固定等级）；
  - 🔴 **等级 > 6 的野怪必定掉装备**，且物品等级贴着怪等级走
    （`drop_for_level`：lv≥7 → i/l 类 7~8 级；lv4~6 → i/j 类 3~6 级）；
  - 窝内最高野怪等级会拉高整窝掉落分布（bucket = max(n, lmax)）；
  - 剩余份数优先给还没掉落的最高等级怪（等级高的先拿、拿好的）。

## 摆放规则
- 合法落点：±1 格 3×3 角点非水 / 非边界外 / 层差 ≤ `--flat-tol`；非树格（允许贴树，官方野怪常在林缘）；
  **脚下那格必须完全同层**（层差 ≥1 = 垂直崖壁，inspect_units 会报「悬崖上」）。
- 出生点周围 6 格留空；守卫点心离建筑 2~5 格、离别的窝 ≥3 格；林中窝之间 ≥6 格（最远点采样铺开，
  同距优先挑树多的）。
- z = 落点四角 WE 均值；creation number 全表重排；重复运行会先清掉旧 owner=12 记录（幂等）。

## 参数
`--guard-share 0.6`（守建筑比例）、`--forest-camps auto|N`（auto = 面积/1024）、
`--camp-scale 1.0`（总量倍率）、`--edge 6`、`--flat-tol 1`、`--drops 1`、`--seed`、
`--preview`、`--out`。GUI 在「第 5 步 · 野怪」面板；`random_map.py` 第 4 步透传。
