# 三步式地形生成方案书

> 目标：把现在的「一条噪声场同时切出水域和层级」拆成三步，让**水 / 山 / 悬崖 / 树**四件事彼此解耦，其中悬崖和树木变成可选项。
> 状态：**已实现**（2026-09-16，P1~P7 全部完成，见文末「实现记录」）。
> 日期：2026-09-16

---

## 1. 现状：水和悬崖是耦合的

`tools/gen_height.py` 现在的主流程（`main()` 第 1202～1258 行）：

| 步 | 做什么 | 关键代码 |
|---|---|---|
| 1 | fBm 噪声 → 高度场 | `height = fbm(nprng, (rows, cols), freq, octaves)` |
| 2 | 按秩重排成均匀分位 | `quant[order] = linspace(0,1,N)` |
| 3 | **同一条分位同时切出水域和层级** | `is_water = quant < water_frac`<br>`lvl = floor(land_q ** level_bias * nlev)` |
| 4 | 众数滤波 / 清碎块 / 限制相邻层差 | `mode_filter` `clean_regions` `limit_neighbor_jump` |
| 5 | 刻斜坡（保证连通） | `carve_ramps` |
| 6 | 层内精细起伏（隆起/凹陷/凹凸/台阶/平整） | `raise/lower/rough/ledge/flat` |
| 7 | 水体：浅水深水 + 水下起伏 | `shelf/deep/water-relief` |
| 8 | 写回 w3e、出预览图 | |

**问题在第 3 步**：`quant` 这一条分位，既决定了「哪里是水」，又决定了「陆地分几层」。于是：

- 想要水域占比 30% → 层级分布也被同一条分位锁死，两者不能独立调
- 想要没有悬崖 → 只能把 `layer_max` 压到 `layer_min`（单层），但此时**水面仍然被强行压到 `layer_min - 1`**，岸边依旧有一整层的落差，而且整张陆地是同一高度的平板
- 「先有水、再长出山」这种自然成因完全表达不出来

## 2. 目标流程：三步

```
┌─ 第 1 步：地形基底（必做）───────────────────────────────┐
│  初始地面（深水 / 浅水 / 平地）                            │
│      +  山脉算法抬升                                      │
│      →  连续高度场 H（WE 高度单位，可为负）                │
│  水面切割：H > 水面 = 陆地，H < 水面 = 水，深度 = 水面 - H  │
└───────────────────────────────────────────────────────────┘
                          ↓
┌─ 第 2 步：悬崖（可选，勾选才做）─────────────────────────┐
│  把连续高度场量化成整层的台阶 → 台地 + 垂直崖壁            │
│  然后按连通性自动刻斜坡                                    │
│  不勾选 = 保持连续缓坡，全图零悬崖                         │
└───────────────────────────────────────────────────────────┘
                          ↓
┌─ 第 3 步：树木（可选，勾选才做）─────────────────────────┐
│  现有树丛播种算法（不动）                                  │
└───────────────────────────────────────────────────────────┘
```

## 3. 统一模型：基准面 + 起伏 → 高度场 → 水面切割

第 1 步的本质是一个很干净的公式。内部**一律用「相对水面的高度」**（水面 = 0，单位是 WE 高度单位），最后写文件时再映射成 `gh` / `layer`：

```python
# 1) 初始地面：一个常数基准面（相对水面）
base = {"deep": -384.0, "shallow": -128.0, "flat": 0.0}[base_mode]   # WE 单位，负 = 水下

# 2) 山脉算法：在基准面上加起伏
H = base + uplift * mountain_field(nprng, shape, ...)     # mountain_field 零均值、单位标准差

# 3) 水面切割（水面 = 0）
is_water = H < 0.0
depth    = -H                      # 只在 is_water 处有意义，深水/浅水由深度阈值切
```

**山脉算法 `mountain_field` 可选三种**（`--mountain`）：

| 值 | 算法 | 观感 | 成本 |
|---|---|---|---|
| `fbm` | 现在的 fBm 值噪声（默认） | 圆润的丘陵团块 | 已有 |
| `ridged` | Ridged multifractal：`1-\|noise\|` 反复叠加 | **有明显山脊线**，最像真山脉 | 几行代码 |
| `warped` | 域扭曲：用一层噪声去扭曲另一层的坐标 | 山体走向自然弯曲 | 几行代码 |

> ⚠️ 提醒：官方对战图实测是「大片平坦面 + 1 WE 量化的陡坎」，**不是**连续山坡。所以 `ridged` 出来的图会**更像真实山脉、更不像官方对战图**。想贴近官方观感，就保持 `fbm` 并配合 `--ledge` 台阶化。

### 水面怎么定（两种模式，二选一）

| 模式 | 参数 | 做法 |
|---|---|---|
| 占比模式（默认） | `--water 0.30` | `S = percentile(H, 30)` 反解水面，保证水域精确占 30% |
| 绝对模式 | `--water-level -50` | 直接指定水面在 WE 高度 -50 |

占比模式只是把分位数算出来，同样简单，而且**不再锁死层级分布**——这是和现状的关键区别。

### 深浅水

不再靠「整层下切」，而是按深度阈值切（这也更接近真实水体）：

| 参数 | 默认 | 含义 |
|---|---|---|
| `--shelf-depth` | 96 | 深度 < 该值（WE）= 浅水，否则深水 |
| `--deep` / `--shelf` | 保留 | 兼容旧的「层」口径（悬崖模式下继续用层） |

## 4. 第 2 步：悬崖 = 把连续高度场量化成层

这是整个方案的关键抽象：**悬崖就是「量化」**。

```python
if cliffs_enabled:
    # 连续高度 → 整层台阶（每层 128 WE），层差的地方自动变垂直崖壁
    layer = layer_min + floor((H - H_min) / 128.0)
    ... 现有 limit_neighbor_jump / carve_ramps / merge_orphan_flats 全部复用 ...
else:
    # 单层：整张图同一个 layer 值，落差全放在 gh 里 → 零悬崖
    layer = layer_min
    gh    = GROUND_ZERO + H * 4            # 4 原始单位 = 1 WE
```

**为什么单层就能有大幅落差**——这条已经被实测证实（315 张官方图，`tools/_tmp/check_gh_deviation.py`）：

| 事实 | 数值 |
|---|---|
| 层内 `gh` 偏离层基准的最大值 | **6144 原始单位 = 1536 WE = 12 层落差** |
| 官方图里层内偏移超过 1 层的角点占比 | **42.9%** |
| 存在「全图只有 1 个 layer 值却有上千 WE 落差」的官方图 | `Human05Interlude.w3m`、`OrcX03a.w3x` |
| 层内坡度对可走性的影响（拿官方 wpm 当标准答案） | 高差 8→192 WE，可走率仅从 87.8% 缓降到 **70.4%**，**没有塌到 0 的阈值** |
| 对照：层差 = 1 且无 ramp | 可走率 **0%** |

> **原则：挡路的只有 `layer` 差异，层内坡度不挡路。**
> 单层模式下近战单位任何一处都能直接走过去，这正是你要的「利于近战兵种」。

### 单层模式下水的处理（重要改动）

现在的代码把水角点强行设成 `water_layer = layer_min - 1`，**所以岸边永远有一整层落差**。单层模式要「平滑入水」，必须改成：

- 水角点**保持和陆地同一个 `layer`**，只把 `gh` 降到水面值以下
- 水是靠 `waterHeight` 字段与角点世界高度比较来渲染的，同层降 `gh` 一样能出水
- 结果：平缓的沙滩，岸边没有崖

```python
# 单层模式：水不换层，只降高度
gh = GROUND_ZERO + H * 4            # H < 0 的地方 gh 自然低于水面
waterHeight字段 = GROUND_ZERO        # 水面恒为 0（相对）
```

### 幅度上限

`gh` 是 u16，`dev = gh - 8192`，官方实测安全范围约 ±8192 原始单位。方案里**默认保守限制振幅**，可手动放宽：

| 参数 | 默认 | 含义 |
|---|---|---|
| `--max-relief` | 512 | 单层模式下 H 的振幅上限（WE），= 2048 原始单位 |
| | | 官方能到 1536 WE，想放开可以调大到 1024～1536 |

## 7. 我对原方案的三点修正（请过目）

| # | 你的原话 | 我的意见 |
|---|---|---|
| 1 | 「选择初始地面情况：深水，浅水，一般平地」 | 建议**不要做成三选一的离散开关**，而是给一个连续的 `--base-level`（初始地面相对水面的高度），深水/浅水/平地只是三个预设值。理由：连续参数能做出「七分水三分地」「水很少的高原」这些中间态，离散开关做不到 |
| 2 | 「这样即使有水也能产生陆地」 | 完全正确，但**副作用是水域占比不再能精确指定**（它变成基准面和起伏幅度的函数）。所以要保留占比模式：`--water 0.3` 时用分位数反解水面，两者都支持 |
| 3 | 「根据选择的高度范围生成悬崖」 | 这句话的本质就是**把连续高度场量化成整层台阶**。建议直接把这个认知写进代码结构：`cliffs=1` 时做量化 + 刻斜坡，`cliffs=0` 时跳过。这样第 2 步是纯粹的一个「后处理开关」，而不是另一套生成逻辑 |

## 12. 第二轮改动：基底语义重定义 + 局部悬崖（2026-09-16 晚，用户新需求）

用户提出两条需求，第 2 条直接**推翻了 §4「悬崖 = 把整个高度场量化成层」的做法**：

> 1. 地形基底的浅水指陆地单位能在上面走的那种，在这个基底上生成的地图应该是没有深水的，
>    而纯陆地的基底生成的地图应该完全没有水
> 2. 勾选悬崖生成后，悬崖地形应该不能是全地图有悬崖，而是只有若干个小块区域有悬崖才比较好

### 12.1 需求 1：`--base` 的三个语义

| `--base` | 语义 | 实现 |
|---|---|---|
| `deep` (-384) | 正常水域，深浅水都有 | 不管 |
| `shallow` (-128) | 水浅到陆地单位能走过去 → **一滴深水都没有** | 整片水域乘一个统一系数压到 `--shelf-depth` 以内，再兜底钳一次（保水底形状，不硬砍出死平湖底） |
| `land` (0) | **一滴水都没有** | 整块抬到水面之上（保形状的平移） |

- 原 `flat` 预设**改名为 `land`**（旧的 flat 就是 0，语义与本需求一致）。
- 新函数 `apply_base_semantics(H, base_mode, shelf_depth)`，在**叠加「应用高度」之前和之后各调一次** ——
  起伏会把水底推深、也会把陆地重新压到水面以下。
- 顺带修掉一个真 bug：量化（`--height-step`）会把水陆分界附近的角点四舍五入到水面的错误一侧。
  原来的修法是「水角点 `fine ≤ -hstep` / 陆地角点 `fine ≥ 0`」—— **只在单层模式下成立**。
  台地角点的层号比水面层高 k 级，它的 `fine` 要低到 `-512k` 才真的沉进水里；只判 `fine < 0`
  会让台地上的水角点反而冒到水面以上（实测 4 个）。现在统一按**世界高度**判：
  `layer_over = (layer - plane_layer) * 512`，水角点 `fine ≤ -layer_over - hstep`、
  陆地角点 `fine ≥ -layer_over + hstep`。

### 12.2 需求 2：局部悬崖

新增三个函数，`--cliffs 1` 不再走「全图层量化 + 全图斜坡」的老路：

| 函数 | 作用 |
|---|---|
| `cliff_mask()` | 用一块**独立**的低频场在陆地上取高分位 → 天然是几大块；众数滤波抹毛边；清掉小于 `--min-island` 的碎块。且**离水 32 WE 以内不选**（台地不下水） |
| `apply_terraces()` | mask 内把高度切成 `Hgap + 128k`、层号 `layer_min + k`（k ≤ `--cliff-layers`）；mask 外紧贴一圈羽化拉平到 `Hgap`、层号 `layer_min` → **边界处落差严格 = 128k = 层差 ✔**（这是 WE 渲崖壁的唯一不变量） |
| `drill_ramps_for_connectivity()` | 连通性**硬兜底**，见 12.3 |

新增旋钮：`--cliff-area`（占比，默认 0.15）/ `--cliff-size`（团块尺寸，26）/
`--cliff-layers`（最高抬几层，3）/ `--cliff-feather`（外围羽化宽度，4）。
`cliff_layers` 被 `--max-jump`、`MAX_LAYER - layer_min`、`layer_max - layer_min` 三重夹住，
保证 `limit_neighbor_jump` 不会改了 layer 却不改高度（那会打破上面那条不变量）。

编码公式也统一了（两种模式同一套）：
`世界高度 = fine/4 + (layer-2)*128 = H_we + (plane_layer-2)*128` —— **与 `layer` 无关**，
台地靠 layer 抬起来、`gh` 就自动少掉 `128k`，台阶面照旧平滑。

### 12.3 连通性：从「靠斜坡算法」改成「有硬保证」

老问题（记录在案）：`carve_ramps` 在**噪声形状的锯齿崖**上成功率不高，会出现
「一座陆地岛被崖壁切成两半」= 游戏里「看得见、过不去」。局部悬崖把这个问题放大了
（每块台地都要有坡才上得去）。三级防线：

1. `carve_ramps`（原逻辑）+ `merge_orphan_flats`；
2. **补刻一遍**：用**最终**的 `is_water` 复查连通性，还断着就再扫一次候选崖段
   （第一遍用过的崖段已被标掉，第二遍看到的是剩下的位置）；
3. **`drop_unreachable_terraces()`**：把够不着的台地整块撤掉 —— `layer` 拉回水面层、
   高度减掉 `128×层差`（正好还原成造崖之前的连续高度），变成普通可走地形；
4. **`drill_ramps_for_connectivity()`**：最后一道。0-1 BFS（可走瓦片代价 0 / 崖壁瓦片代价 1）
   从每座岛最大的可走块出发，找到通往其余可走块的最便宜路径，把路径上的崖壁瓦片
   四角都打上 `0x10` —— **斜坡瓦片按定义可走**，于是必然接通，完全不依赖斜坡算法成功率。

`ramp_report()` 的判据也跟着改了：原来要求「每块的垂直厚度都恰好 3 条角点线」，
那是官方**网格对齐**崖壁的统计主导值（252/356），局部悬崖的锯齿边界做不到也不该做。
现在只看真正的不变量：**不能出现「既不是台阶也不是基地」的非法瓦片**。

## 13. 第三轮改动：斜坡「凹到地心」 + 斜坡合法性（2026-09-16 傍晚，用户反馈）

### 13.1 用户反馈
> 「你这个斜率太大了，都凹陷到地心了，明明加个一般斜坡就行」

### 13.2 根因：坡面被按到了「层基准线」
斜坡瓦片的角点高度走的是和普通地面同一条公式
`世界高度(WE) = fine/4 + 128×(layer-2)`。而 `fine` 是从宏观高度场算出来的：
台地地面的 `fine ≡ 4×Hgap`（`Hgap` 是几十~几百 WE 的地形高度），层号只负责再抬 `128k`。

老代码为了「坡面不能带起伏（否则像搓板）」，直接把坡带角点的 `fine` **清零** —— 那等于把
坡面按到**层基准线**上（`世界高度 = 128×(layer-2)`），离台地地面整整差一个 `Hgap`。

实测（seed=777，128×128，`--base land --cliffs 1`）：

| | 坡面世界高度 | 紧邻台地地面 |
|---|---|---|
| 修复前 | **1 ~ 256 WE** | 550 ~ 620 WE |
| 修复后 | **258 ~ 787 WE** | 379 ~ 814 WE |

修复前就是一条比周围低 400~500 WE 的深沟 —— 用户说的「凹到地心」。

### 13.3 修法：坡带高度取「**同层号、且朝台地那一侧**的地面高度」

`fill_band_fine(fine, layer, band, radius=8, win=4)`：

1. **局部 PCA**：取该角点 `win`(4) 格邻域内的坡带角点，主轴 = 坡带切线，法线 = 主轴转 90°；
2. 用「层号高的角点在法线正侧」定出朝向 —— 低层线取 −法线（下坡台地）、高层线取 +法线（上坡台地）；
3. 把方向**吸附到 8 邻域里的一个**，沿**严格直线**逐格出射，取第一个命中的**同层号、非坡带**
   角点的高度；
4. 找不到（整条坡带同层、或严格方向上够不着）→ 退化成半径内任意同层号角点平均 → 盒式模糊兜底。

结果：**坡带的低层线 = 下台地地面高度，高层线 = 上台地地面高度**（逐角点精确复制），
坡面落差 `≈ 128×层差`（再叠加两侧台地各自的 `fine` 起伏差），跟 WE 渲染斜坡的方式一致。

⚠️ 三个绝对不能回退的点：
- **不能不分层号地做邻域平均**（最早的兜底做法）：坡带会拿到两个台地高度的中间值，
  上层线比它该贴的台地低一截、下层线又高出一截，坡面中段还会鼓包。
- **不能用「点积 ≥ 阈值」代替方向吸附**：坡带是「垂直崖壁的一条带」，沿坡带**切线**方向
  挨着的普通地面是崖壁上下方的地面本身，常常正是地形陡降处。放成「点积 ≥ 0.5」时 45° 斜邻居
  （点积 0.707）也会被当成「朝着台地」；即使收到 0.8，坡带**中间那条线**的正对面就是坡带自己，
  最先命中的同层号地面仍可能是斜向的切向地面 —— 实测 seed=777 站点 #5 中间线被拽低 42 WE，
  坡面变成「先下后上」的 V 形沟。
- **不能整条坡带连通簇只算一根法线**：一块区域里多条斜坡会连成一片
  （实测 `验收_局部悬崖` 有一块 21 个瓦片把几条坡连在一起），簇级法线对不上，
  坡面又会取到切向的低地形 —— 站点 #16 偏差 85~127 WE。改成**局部窗口**后同一站点变成精确复制。

修后同一站点剖面（文件行序，`*` = 坡带）：
```
 r56  2/294  2/286  2/270  2/258  2/258      ← 低台地
 r57  2/294  2/286  2/270  2/258  2/258*     ← 坡带低线（= 低台地）
 r58  2/294  2/286  2/270  2/258  3/344*     ← 坡带低线（= 低台地）
 r59  3/331  3/343  3/338  3/336  3/344*     ← 坡带高线（= 高台地）
 r60  3/331  3/343  3/338  3/336  3/344      ← 高台地
```
逐角点精确贴合。`ramp_slope_probe.py` 量得该站点坡面下探从 **-63 → -26 WE**。

### 13.4 顺带修掉的斜坡合法性 bug（多遍刻坡的重叠）
- `carve_ramps(prev_ramps=...)`：第二遍补刻时不能「以为地图上没有斜坡」而在旧斜坡上平移重刻；
- `_stamp_ramp` 既有占位守卫：落点已被占用且层位不同于目标 → 直接放弃该落点；
- `_stamp_would_be_legal()`：试算盖下去后邻域会不会留下「四角全带 ramp 位但层位非法」的瓦片；
- `drill_ramps_for_connectivity()` 只从 `spread==1`（层差恰好 1）的崖壁开坡，
  且每盖一格试算 `_illegal_ramp_count`，会产生非法坡就撤销（返回 `(ramp, opened, reverted)`）；
- `cliff_mask` 加 `solid` 填洞 + 距地图边留 3 格；`_lipschitz_levels()` 把台地级数场
  约束成「相邻格最多差 1 级」（遮罩外视为 0 级）→ 遮罩边界落差恒 ≤1 级，斜坡跨得过去。

| 指标 | p10 | **p50** | p90 |
|---|---|---|---|
| 树密度（占全图） | 8.4% | **12.0%** | 19.0% |
| 连片块数 | 72 | **256** | 391 |
| 最大连片块 | 119 | **205** | 382 |
| ≥100 格大林块数 | 1 | **4** | 12 |
| 树落在 ≥100 大林的比例 | 6.7% | **33.2%** | 57.9% |

**密度 34%（= 官方的 3 倍）+ 每丛都是等大的 26 株圆斑** → 250 个等大圆点撒满全图。

**结论 2**（关键，靠渲染才看出来）：把官方图的树掩码画出来（`render_official_trees.py`）——
Harrow 是**贴着地图边框的一圈粗林带**；LostTemple 是**沿地图边与基地外缘的粗林带**；

内部才是零散小簇。我们完全无视地形边界，所以怎么撒都是均匀斑点。

### 14.2 新算法：三层播种 + 边界林带

`tools/add_doodads.py` 的 `place_clumps` 换成四个函数：

| 函数 | 作用 |
|---|---|
| `build_forest_field` | 森林场 = **边界林带** × 沿边噪声 + 内部低频 fBm（只当权重，不切阈值） |
| `build_fine_field` | 细尺度噪声场，给区域生长当「代价抖动」，把边界打毛 |
| `grow_region` | **加权最短路（堆 Dijkstra）区域生长**，长出大林 |
| `place_forests` | 挑林核（森林场² × 随机）+ 间距守卫，逐核长成大林 |
| `place_groves` | 小林丛：重尾株数 + 椭圆 + 噪边 + 丛心禁区 |
| `place_scatter` | 散株，优先落森林场低的空旷地 |
| `grow_along_edge` | 株数没配平时沿林缘外扩（**绝不随机撒孤立单株**） |

边界林带用 `dist_transform(elig)`（到不可种区的 8 邻接距离）做 `exp(-d/带宽)`，
再乘一层沿边 fBm 把林带**打断成一段段** —— 不打断的话整圈林带会连成一个巨型块
（实测最大连片块飙到 1000+，官方 p50 只有 205）。

### 14.3 走进的三个坑（都靠量化指标抓出来）

| 坑 | 症状 | 修法 |
|---|---|---|
| 核间间距按**中位**尺寸算 | 7 个核长完粘成 897 格巨块 | 间距按 **max_clump = 2.2×中位** 算 |
| 把「核间间距」误当「离地图边余量」 | 128 的图里一个核都放不下（余量 61 > 半张图） | 边距单独用 `sqrt(max_clump/π)+2` |
| `grow_region` 只在局部「择优邻居」 | 大林顺边界林带长成一条**长蛇**，3 个核串成 1572 格 | 改成**加权最短路区域生长**（代价 = 路径长度），整体紧凑、沿走廊拉长 |
| `place_groves` 禁区窗口用 `mgrid[y范围, x范围]`，填充窗口用 `mgrid[x范围, y范围]` | 两者轴向相反 → 禁区被写成转置形状，圈错地方，95 个丛只剩 9 个块 | **全项目统一**：窗口切片一律 `[x 范围, y 范围]`，抽了 `_ellipse_drop()` 单一出口 |
| 丛间距只按 `丛半径` 留 | 两个半径 3 的圆盘中心隔 5.7 格必然相接 → 连成一整张网 | 禁区半径 = **2×丛半径 + 空隙** |
| 没有细噪声 | Dijkstra 在均匀场上是**完美菱形**（L1 测地球），一眼假 | 边权乘 `1 + 3.0×(细噪声-0.5)` |

## 15. 第五轮改动：树林「胡椒点」根治 + 指标口径收敛（2026-09-16 晚，用户反馈）

### 15.1 用户反馈

> 「树林的生成算法可能需要修改一下，目前树林都是像斑点一样分散在地图中，有没有什么办法
> 让树林更像实际地图中的树林，至少也不要像斑点一样分布」

第四轮（第 14 节）已经把三层播种 + 边界林带做出来了，量化指标也「对上了」官方 p50。
但**把官方图和我们的产物并排画出来（`out/forest_compare.png`）就发现：统计像、观感不像** ——
我们是「一片片中等大小的团 + 满地孤立小点」，官方是「少数几片大林 + 大林的毛边」。

### 15.2 诊断：先给「胡椒点」下量化定义，再动手

新增三个指标（都按**树数**归一，写进 `add_doodads.forest_metrics`）：

| 指标 | 含义 |
|---|---|
| `iso8` | 8 邻域内一棵邻树都没有的树占比 |
| `iso2` | **2 格**邻域内一棵邻树都没有的树占比 ← 最灵敏 |
| `dmed` / `dnear` | 树到最近「大林（≥100 格块）」的格距中位 / ≤3 格占比 |

量官方 43 张 1.27a 原生对战图（`tools/_tmp/forest_official_stats.py`，全量分位进
`foreststats_melee.txt`）：

| 指标 | p10 | **p50** | p90 |
|---|---|---|---|
| 树种密度 | 0.084 | **0.120** | 0.190 |
| `iso8` 8 邻域孤立株占树数 | 0.004 | **0.017** | 0.034 |
| `iso2` 2 格内无树占树数 | 0.000 | **0.001** | 0.004 |
| 到大林格距中位 | 0 | **10** | 42 |
| 距大林 ≤3 格占树数 | 0.088 | **0.365** | 0.642 |
| 孤立单株占块数 | 0.373 | **0.488** | 0.590 |
| 块数/树数 | 0.0408 | **0.0924** | 0.1500 |

我们的产物（GUI 全链路）：`iso8` **0.030**、`iso2` **0.018**、`dmed` 8~13、`dnear` 0.30~0.42。

**结论（很反直觉，值得记住）：**

- 「到大林的距离」我们其实**早就对齐官方 p50**（`dmed` 8~13 vs 10、`dnear` 0.30~0.42 vs 0.365）。
  之前用 4 张手挑的密林图量出「官方 dmed = 0」是**取样偏差**，不是真目标。
- 真正的超标项只有一个：**`iso2` 我们 0.018，官方 0.001 —— 高了 18 倍**。
  也就是说官方地图里「一棵树周围 2 格内连第二棵树都没有」几乎不存在，
  而我们的散株是**按 `(1-森林场)` 逐格独立抽样**的，撒出来就是满地胡椒点。

> 教训：**不要用手挑的几张图当基准**。43 张全量的 p50 和 4 张精挑的「典型图」能差出一个数量级。

### 15.3 修法：散株也必须成团（`place_scatter` 重写）

一层改动，直击 `iso2`：

1. 按 `(1-森林场)` 加权挑「丛心」（和旧版一致，空旷地优先）；
2. **每个丛心只在自己 3×3 窗口内**补 `quota` 格（配额取对数正态、中位 `--scatter-size`）；
   窗口就这么大 → 补出来的树**必然互为 8 邻域**，`iso2` 直接归零；
3. `quota` 抖动到 1 的那一小撮，就是官方那种「真孤立单株」，比例自然落在 1~2%。

调参（`tools/_tmp/forest_sweep.py`，6 种子纯网格）：`--scatter-size` 是最关键的旋钮。

| 官方 p50 | 0.017 | 0.001 | 0.488 | 0.0924 |
| 1.0（= 旧的单点撒） | 0.021 | **0.005** ✘ | 0.527 | 0.098 |
| **1.5（新默认）** | **0.015** | **0.002** | **0.506** | **0.098** |
| 2.0 | 0.014 | 0.001 | 0.465 | 0.093 |

`1.0` 就是胡椒点（`iso2` 冲到官方 p90）；`1.5` 四项全中 → 定为默认。

### 15.5 指标口径收敛：**全项目只有一份实现**

这一轮踩了一个很难发现的坑，值得单独记：

`forest_official_stats.py` 曾经自己抄了一份「是否孤立」的代码，写成
`t & ~dilate(t, 1)`。而标准 `dilate` 的语义是 `mask ∪ 邻域`（**含自身**），
于是 `~dilate` 在任何 tree 格上恒 False → **孤立率恒为 0**。
它不报错、不崩，只是安静地给出「官方 43 张图孤立率全都是 0」这个荒谬结论，
我据此还误判过一轮。改成 `t & ~(dilate(t,1) & ~t)` 又恒为 1，再次被骗一次。

修法两条，缺一不可：

1. 新增 `add_doodads._neigh_any(mask, r)`：**从全零开始 OR 位移副本、永不含 (0,0)**，
   语义就是「这一格的 r 邻域里有没有**别的** True」；三个脚本全部改成调它（口径唯一）。
2. 新增 `tools/_tmp/test_forest_metrics.py` —— **31 项手工可算的小例子**把语义钉死
   （单点 / 正交相邻 / 对角相邻 / 相距 3 格 / 5×5 方块 / 阈值边界 / 切比雪夫距离）。
   这类算子写错**不会报错**，只能靠单元测试。

顺带统一到 `forest_metrics`：GUI 日志、`forest_sim.py`、`accept_forest.py`、
`forest_official_stats.py` 现在共用同一份指标与同一组官方 p50 常量。
